# Сквозная проверка поиска, источников и Telegram

Дата: 1 октября 2026 года. Это новая проверка текущего кода, а не повтор
цифр из прежних отчётов.

## Что было проверено на реальных ответах

- Локальный Docker сначала работал без `queue`: `web`, scheduler, Redis и
  PostgreSQL были запущены, но поиск оставался в состоянии ожидания. После
  запуска worker очередь из 56 старых заданий обработалась, а источники
  ответили. В production worker запущен, очередь в момент проверки пуста.
- «разработка сайта»: одна открытая B2B-карточка №4616411, срок 9 октября;
  посторонние карточки в личной теме не показывались. Workspace.ru ответил,
  но дополнительных действующих совпадений этой темы не дал.
- Заведомо отсутствующая фраза `zzzxqv-20261001`: B2B вернул свой настоящий
  пустой ответ. Workspace.ru имел только более ранний общий снимок; UI теперь
  называет его старым, не засчитывая свежим ответом для нового мониторинга.
- «строительство»: публичная первая страница B2B дала 20 строк. До исправления
  все 20 попали в ленту, включая аренду ДГУ: внутри HTML заголовка был вложен
  блок с категорией «строительство». После удаления вложенной метаинформации
  и повторного импорта осталось семь тематических заголовков. Оригинальные
  карточки сохранены, ложные связи с темой удалены.
- Повторный поиск «разработка сайта» вернул ту же одну карточку без дубликата.
  Просроченные карточки отсекаются при начальном заполнении и перед
  асинхронным сопоставлением; это дополнительно покрыто существующими тестами.
  Чужие совпадения и состояния проверены через серверные тесты доступа.

## Доставка

Новый интеграционный тест проходит путь: первый снимок B2B без рассылки →
новая карточка после него → личное совпадение только связанного мониторинга →
одна запись доставки → вызов Telegram-клиента с ID нужного пользователя →
`sent`. Повторный импорт не создаёт вторую доставку. Telegram API в тесте
имитирован. Локальный контур не содержит bot token, поэтому реальное сообщение
от локальной проверки не отправлялось.

Read-only production-аудит до нового релиза: 50 Workspace-карточек, 21 B2B,
последние их опросы успешны; `queue:monitor` показал 0 ожидающих заданий.
Среди исторических `tender_card` есть одна запись `failed` с безопасным
кодом `telegram_delivery_failed`. Нового подходящего тендера для безопасной
проверки реального получения в Telegram пока не было. Исторические импорты
повторно не рассылались. Статус `sent` для уведомлений о ручном доступе,
описанный в прежнем отчёте, не подтверждает доставку нового тендера.

## Отдельный ручной UI/UX-осмотр

На 390×844 осмотрены первый экран onboarding, пустая и заполненная лента,
панель источников, длинные B2B-заголовки, мастер мониторинга и профиль
уведомлений. На широком экране осмотрен первый вход. Поле и кнопка поиска
видны на первом экране ленты; настройка мониторинга доступна из панели
источников, мгновенные уведомления включаются в профиле. `scrollWidth`
совпал с `innerWidth` на мобильных экранах. Проверены состояние отключённой
кнопки мастера, ожидание ответа, раскрытие панели, отступы, переносы
заголовков и нижняя навигация. Фраза «по сохранённым карточкам» в основном
интерфейсе не встречается. Настоящий Telegram Mini App и тёмная тема на
устройстве этой проверкой не охвачены.

После исправления заголовков по «строительство» на мобильном экране видны
семь карточек с самой темой в названии. Для контрольного пустого запроса
заголовок ленты больше не объявляет завершённый поиск, пока Workspace
показывает лишь старый снимок. Проверка, стоящая в очереди больше двух минут,
получает отдельное состояние задержки вместо бесконечного «проверяем».

## Границы охвата

Workspace.ru — текущие 50 RSS-записей; B2B-Center — первая страница
публичной фразовой выдачи. Гостевая B2B-страница показывает номера следующих
страниц без открытых ссылок, поэтому адрес и контракт пагинации не
подтверждены. Сбер АСТ, Росэлторг и РТС-Тендер к активному общему поиску не
добавлены. Строгий поиск по словам может пропустить синонимы и общие
заголовки без слов темы.

## Проверки выпуска

Перед коммитом локально прошли `php artisan test --compact` (213 тестов,
2345 assertions), `phpstan analyse --memory-limit=1G` (0 ошибок),
`pint --test` (313 файлов), `npm run lint`, `npm run format:check`,
`npm run build` и `git diff --check`.

### Выпуск исправления поиска 1 октября

Коммит `1ae9946` прошёл CI в `SLSforme/saas-bot` и
`Oleqq/tender-finder`. Перед ручным релизом создан и проверен `gzip -t`
снимок PostgreSQL; SHA-256 исходного архива совпал на Mac и VPS. Штатный
`deploy/vps-deploy.sh` собрал образы, сообщил `Nothing to migrate` и
перезапустил приложение. Внешний `/health` вернул HTTP 200. `web`, `queue`,
scheduler, PostgreSQL и Redis работали; `queue:monitor redis:default` показал
ноль ожидающих, отложенных и занятых задач. `migrate:status` не обнаружил
неприменённых миграций. Это подтверждает развертывание и исправность контура,
но не фактическое получение новой карточки конкретным пользователем в
Telegram.

Последующая read-only проверка после релиза показала два успешных B2B-опроса
(20 и одна запись) и 47 накопленных B2B-карточек. У Workspace.ru последний
опрос завершился `connection_failed`; предыдущий вернул 50 RSS-записей.
У RosTender последний ответ — `remote_quota_or_access_denied`. Поэтому
общий поиск нельзя считать одинаково доступным во всех источниках в каждый
момент; B2B продолжил работать, а состояние сбоя Workspace должно быть видно
пользователю. `tender_card` в production по-прежнему имеет одну историческую
неудачную доставку и ни одной подтверждённой новой успешной.

### Вход Mini App 2 октября

Пользователь показал экран с требованием открыть приложение из Telegram,
хотя Mini App уже открыт внутри Telegram Desktop. В production-журнале два
запроса `/telegram/session` в 01:28 по Москве отклонены с причиной
`Telegram auth data has expired`. Прежний предел `auth_date` составлял пять
минут, а UI проглатывал ответ 422 и показывал общую подсказку. Исправление
сохраняет проверку HMAC-подписи и ограничение срока, увеличивает допустимый
возраст подписанного `initData` до суток и различает ожидание, истечение,
отсутствие данных и сбой соединения. При сбое есть кнопка повтора; при
действительно устаревшем `initData` предлагается закрыть окно Mini App и
открыть его заново. Подтверждение повторным входом в Telegram Desktop после
релиза ещё требуется.
