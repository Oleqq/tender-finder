# Т-Банк: разовая оплата и сверка

Код добавлен в основной репозиторий 4 ноября; состояние сверено 10 ноября
2026 года. Выбран провайдер Т-Банк для ИП;
новые платежи ЮKassa отключены в коде, включая случай старого enabled-флага.
Чтение исторических платежей ЮKassa сохранено. 9 ноября добавлен внутренний
платёжный контур: реальные заказы, попытки, сверка и однократная выдача доступа.
Публичная покупка и автосписания не открыты; все три флага Т-Банка выключены.
Установленный выпуск указан в [CURRENT-STATE](CURRENT-STATE.md).

## Реализовано

- `TBankClient`: подписанные JSON-запросы `Init`, `GetState`, `CheckOrder`
  на фиксированный официальный адрес `https://securepay.tinkoff.ru/v2/`.
  Установлены тайм-ауты, запрет автоматических повторов и HTTP-редиректов,
  ошибки без сырого ответа банка, пароля и данных покупателя.
- `TBankToken`: SHA-256 по отсортированным значениям корневых параметров
  с паролем терминала. Вложенные `DATA`/`Receipt` не участвуют; boolean
  сериализуется как `true`/`false`. Проверка через `hash_equals`.
- `TBankCheckoutRequestFactory`: заготовка разовой одностадийной оплаты
  `PayType=O` из утверждённого серверного `subscription_orders` snapshot,
  RUB/копейки, одна позиция цифровой услуги и e-mail чека. Demo, другой
  провайдер, несогласованная сумма и автопродление отклоняются. Цены не
  принимаются от браузера. Фискальные параметры не выбраны за бухгалтера:
  без них запрос не строится. Срок платёжной ссылки ограничен `expires_at`
  заказа. Полный фискальный цикл пока не реализован.
- `TBankPaymentVerifier`: повторный `GetState`, сверка терминала, PaymentId,
  OrderId и суммы с ожидаемыми значениями из сохранённого платёжного
  намерения. Только `CONFIRMED` возвращает true; `AUTHORIZED` означает холд,
  возвраты и промежуточные состояния не подтверждают покупку.
  Метод только читает, доступ не выдаёт.
- `POST /payments/tbank/notifications`: отдельный API-маршрут без браузерной
  сессии/CSRF. Проверяет JSON, размер, TerminalKey и Token; затем сохраняет
  минимальное событие в `tbank_notifications` и отвечает строго `200 OK`
  с телом `OK`. Уникальный SHA-256 ключ события исключает повторы.
  Статусы сохраняются отдельно, порядок доставки не считается достоверным.
- В журнале есть request_id, ключ события, статус и признак повтора.
  В таблице и этом журнале нет Token/Password, Pan/ExpDate, RebillId или
  e-mail. Полный webhook не сохраняется. Ошибка БД не подтверждается `OK`.

### Платёжный контур от 9 ноября

- `TBankOrderService` создаёт разовый заказ только для собственного проверенного
  Telegram-аккаунта после окончания доступа и с актуальными согласиями.
  Цена, период 1/3/12 месяцев, лимит, юридические версии и чек фиксируются на
  сервере. Demo/гости и покупка поверх действующего доступа отклоняются.
  Это внутренний сервис без пользовательского маршрута; он не решает будущую
  привязку самостоятельного веб-покупателя к аккаунту.
- Одна `tbank_payment_attempts` на заказ; уникальная пара терминал/PaymentId.
  E-mail/запрос и PaymentURL зашифрованы, не попадают в сериализацию модели.
  Локальный ключ повтора ограничен владельцем и параметрами покупки.
- `TBankPaymentService::initialize` сначала действительно коммитит маркер
  попытки, затем делает один `Init` без HTTP-повторов. Ответ проверяется,
  PaymentId и безопасная HTTPS-форма `securepay.tinkoff.ru` сохраняются до
  возврата ссылки. Повтор читает сохранённую попытку. Тайм-аут/падение не
  разрешает новый Init или новую покупку: сначала `CheckOrder`, ровно одна
  совпадающая попытка, затем `GetState`. Неоднозначность требует разбора.
- Сверка использует свежий `GetState`: терминал, PaymentId, OrderId, сумма и
  `CONFIRMED`. Блокировки user → order → attempt и сохраняемая lease с токеном
  не допускают параллельную обработку одной попытки. Подписка `source=tbank`,
  entitlement и аудит записываются атомарно один раз. Оплаченный срок начинается
  при проверенной выдаче; задержка уведомления не съедает период. Автопродление
  всегда выключено. Позднее согласие/доступ не перезаписываются: заказ → `review`.
- `payments:reconcile-tbank --limit=10` запускается каждую минуту, обрабатывает
  незавершённые попытки и inbox. Уведомление только запускает свежую проверку;
  `received` и подпись не являются подтверждением оплаты. Ошибка/падение
  восстанавливаются после lease/backoff. Незнакомые заказы повторяются до
  12 попыток, затем требуют разбора; подмена суммы/PaymentId отклоняется.
  Возвраты переводятся в `review`, без автоматического изменения доступа.

Для разбора: `payments:reconcile-tbank --attempt=<UUID> --retry-review` повторяет
проверку банка, но не Init, не обходит активную lease, согласия или доступ.
Команда выводит только состояние/код, без платёжной ссылки и данных покупателя.
`TBANK_ENABLED=false` прекращает новые платежи, независимая сверка может
завершать уже созданные. При выключенной сверке команда делает no-op без API.

## Настройки

Секреты задаются только в окружении сервера; `.env.example` содержит пустые
поля. Тестовые credentials не должны попадать в чат или Git.

| Переменная | Назначение |
|---|---|
| `TBANK_ENABLED=false` | Запрет новых вызовов Init по умолчанию. |
| `TBANK_NOTIFICATIONS_ENABLED=false` | Независимый переключатель inbox. При выключении ответ 503. |
| `TBANK_RECONCILIATION_ENABLED=false` | Независимое чтение состояния банка, consumer inbox и выдача доступа. |
| `TBANK_TERMINAL_KEY` | Терминал из кабинета интернет-эквайринга. |
| `TBANK_PASSWORD` | Пароль терминала для подписи API и проверки уведомлений. |
| `TBANK_PUBLIC_BASE_URL` | Заданный оператором HTTPS origin сайта, без пути/query/userinfo/порта; не Host из браузера. |
| `TBANK_REQUEST_TIMEOUT_SECONDS=15` | Тайм-аут, ограниченный диапазоном 1–60 секунд. |
| `TBANK_RECEIPT_TAXATION` | Система налогообложения, утверждается бухгалтером. |
| `TBANK_RECEIPT_TAX` | Ставка/признак НДС, утверждается бухгалтером. |
| `TBANK_RECEIPT_PAYMENT_METHOD` | Признак способа расчёта. |
| `TBANK_RECEIPT_PAYMENT_OBJECT` | Признак предмета расчёта цифрового сервиса. |

Провайдерский тестовый терминал не заменяется demo-режимом приложения.
Используется тот же официальный URL API, а тестовый режим определяется
выданным банком терминалом. Перед настройкой уведомлений применить миграцию
`2026_11_04_120000_create_tbank_notifications_table` и
`2026_11_09_120000_add_tbank_payment_attempts`.
В кабинете терминала NotificationURL после выпуска:
`https://tenderfinder.ru/payments/tbank/notifications`.
Не включать его до приёмки тестового терминала и утверждения пути покупки/чеков.

Остановка продаж: `TBANK_ENABLED=false`. `GetState` и `CheckOrder` остаются
доступны при действующих credentials; inbox управляется независимо, чтобы
не терять завершения старых платежей после остановки новых продаж.
Ни один флаг сам по себе не создаёт публичный checkout.

## Что требуется для полного подключения

1. Получить тестовый терминал и пароль интернет-эквайринга Т-Банка для ИП.
   Утвердить с бухгалтером схему кассы, ФФД, ставку НДС, признаки расчёта
   и предмета расчёта; при предоплате — необходимость закрывающего чека.
   Текущая фабрика поддерживает базовую позицию услуги; выбранную кассу
   и формат чеков нужно проверить отдельно.
2. Подтвердить связь самостоятельного веб-покупателя с его Telegram-аккаунтом.
   Нельзя использовать введённый чужой Telegram ID как доказательство владельца.
3. Заказы и платёжные попытки реализованы 9 ноября внутренним сервисом.
   `SubscriptionOrderService`/`CheckoutProvider` продолжают обслуживать demo;
   публичный внешний checkout ещё нужно спроектировать и подключить после пункта 2.
4. Сохранение результата Init, проверка банковской формы и восстановление через
   CheckOrder реализованы. Требуется приёмка поведения настоящего терминала.
5. Consumer inbox, повторный GetState и однократная атомарная выдача доступа
   реализованы. SuccessURL/FailURL по-прежнему информационные `/pricing`.
6. Реализовать операторские возвраты через `Cancel`, учёт полных/частичных
   возвратов, сверку, чеки и применение утверждённых правил к доступу.
7. Автопродление — отдельный этап: явное согласие на сохранение способа
   оплаты, разрешение банка, защищённый RebillId, рекуррентные вызовы,
   уведомление за 24 часа и связь с уже реализованной отменой через `/cancel`,
   общей блокировкой и остановкой новых попыток.
   Источник `tbank` учитывается в доступе, lifecycle и общей остановке auto_renew.
   Модуль расписаний всё ещё использует прежний scope `yookassa`; согласия,
   уведомления и charge worker Т-Банка нужно добавить отдельно.
   Не переносить demo/старые согласия автоматически на новый провайдер.
8. Тестовый терминал: успешный/отклонённый/задержанный платёж, дубль и
   перестановка webhook, подмена суммы/терминала/заказа, тайм-аут Init,
   ошибка БД, возврат, чек, истечение доступа. Затем CI, резервная копия,
   выпуск с выключенными продажами и контролируемая приёмка.

Путь продажи остаётся самостоятельным внешним сайтом. В Mini App кнопка
внешней оплаты не добавлялась; смена банка сама по себе не меняет выбранную
границу Telegram. Общий план: [PAYMENTS-NEXT-STAGE](PAYMENTS-NEXT-STAGE.md).

## Проверки

Код 9 ноября: 609 PHP-тестов / 7120 assertions, 17 JS-тестов,
PHPStan/Pint, Vite и ESLint. CI точного SHA:
[основной](https://github.com/slsforme/saas-bot/actions/runs/42585171623),
[зеркало](https://github.com/Oleqq/tender-finder/actions/runs/42585176210).
Установка прошла 9 ноября, завершающая проверка VPS завершена 10 ноября:
исходники/контейнеры совпали, миграции применены, все флаги выключены,
сверка делает no-op без обращения к банку. Подтверждённые факты
и резервная копия — [CURRENT-STATE](CURRENT-STATE.md).

`TBankIntegrationTest` покрывает Token, transport, фабрику чека и приём inbox.
Новый `TBankBillingTest`: 42 сценария / 340 assertions, реальные коммиты без
внешней транзакции раннера, Init один раз, сбои сети/процесса/БД, CheckOrder,
чужие заказы, шифрование, повтор/ранний webhook, backoff и lease, изменение
согласий или доступа, возврат и истечение подписки. Только HTTP fake и
изолированная тестовая БД; никаких настоящих ключей и банковских запросов.
Это не приёмка банковского терминала, внешнего checkout или полного фискального цикла.

```sh
docker --context default compose -f compose.local.yml -f compose.local.dev.yml run --rm --no-deps --entrypoint php test artisan test --compact --filter='TBankIntegrationTest|TBankBillingTest|YooKassaClientTest'
```
