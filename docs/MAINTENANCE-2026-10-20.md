# TenderFinder: проверка 20 октября 2026

## Область проверки

Оба GitHub `main` до изменений указывали на `90491c8`, без расхождений с
локальным checkout и маркером VPS. CI на этой ревизии был зелёным в обоих
репозиториях. На VPS проверены состав контейнеров, миграции, HTTPS `/health` и
`/open?screen=plans`, очередь, расписание, резервные копии, место и память,
последние логи и агрегаты БД. Производственные данные не менялись при аудите.

Шесть контейнеров работали, `web`, PostgreSQL и Redis были healthy. Оба
проверенных HTTPS-маршрута ответили `200`. Redis-очередь была пустой; в логах
приложения за сутки не обнаружено новых `ERROR`. Ежедневный backup timer
активен; архив от 20 октября прошёл `gzip -t`, имеет режим `600`. На диске
оставалось около 12 ГБ из 48 ГБ, доступно около 2,6 ГБ RAM из 3,8 ГБ.

На момент среза в БД: 3 `subscriber`, 3 `super_admin`, 5 активных мониторингов,
0 платежей. За 24 часа зафиксированы по одной успешной доставке карточки
тендера, дайджеста и напоминания об окончании trial. `sent` означает принятие
Telegram API, а не доказательство чтения пользователем. Источники Workspace,
B2B-Center, Bidzaar, ЭТП Регион и часть каталогов имели успешные запуски.
У RosTender сохраняется отказ квоты; у каталогов Росэлторга, РТС-Тендер и
Сбер АСТ встречались ошибки соединения и отдельные `502`. Эти сбои не следует
показывать пользователю как отсутствие тендеров.

## Найдено и исправлено

- В `production` был установлен `QUEUE_FAILED_DRIVER=null`, а таблица
  `failed_jobs` отсутствовала. Поэтому `queue:failed` не сохранял и не
  показывал упавшие задания. Добавлена обратимая миграция, а пример
  конфигурации переведён на `database-uuids`. При выпуске отдельно нужно
  переключить закрытый `.env.production` и пересоздать процессы Laravel.
- У общего CSS и Tailwind были разные семейства шрифтов. Единый стек теперь
  задан через `--font-sans`; в браузере он вычисляется как Inter/SF Pro Text/
  Segoe UI с системными запасными шрифтами.
- Общие маленькие кнопки, фильтры, раскрывающиеся строки и стрелки календаря
  получили минимальную высоту касания 44 px. На 320 px длинные подписи верхней
  навигации заменены короткими видимыми подписями с полным доступным названием.

## Проверка интерфейса и сценариев

В изолированном локальном Docker-контуре с чистой БД проверены 19 маршрутов:
обзор, лента, мониторинги, участие, аналитика, календарь, профиль, тарифы,
команды, поддержка, её админка, платёжная админка, операции, согласия,
онбординг, карточка тендера и работа с ней, оферта, политика. У всех
проверенных страниц одна оболочка и нет горизонтального переполнения на
390 px. Основные пользовательские экраны также проверены на 320 px.

С нуля пройдено: локальный вход нового subscriber → onboarding → два
раздельных согласия → запуск 72-часового trial → пустая лента → создание
мониторинга → статус источников → тарифы → обращение в поддержку. Источники
в локальной сети не ответили; интерфейс показал «Источник недоступен»,
а не «тендеров нет». После CSS-правок календарь на 320 px не переполняется,
стрелки имеют 44 px, основной шрифт вычисляется одинаково.

Нативное окно Telegram Desktop отображало production Mini App, но доступный
инструмент macOS не смог передать ему нажатия. Поэтому нативная приёмка
каждого экрана, платёж через Telegram Stars, реальная отправка нового
уведомления и сценарии другого устройства этой проверкой не подтверждены.
Stars в production выключены, цены планов — 0 XTR; включение платежей
остаётся отдельной приёмкой по [runbook](TELEGRAM-STARS-RUNBOOK.md).
Владельческий доступ Telegram ID `844023492` не менялся.
