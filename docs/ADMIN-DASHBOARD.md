# Маркетинговая админка

Экран выпущен на VPS. Это закрытая агрегированная аналитика аудитории,
не техническая консоль и не подтверждение запуска продаж.

## Назначение и доступ

`GET /operations` доступен только серверной роли `super_admin`;
`/operations-demo` — защищённый редирект. Экран не раскрывает Telegram ID,
имена, username, поисковые фразы, содержимое выдачи, payload доставок,
очереди и инфраструктуру. Поддержка — [отдельное рабочее место](SUPPORT-WORKSPACE.md).

Периоды — `7d`, `30d`, `90d`, по умолчанию `30d`. Границы — от начала
календарного дня в часовом поясе приложения до формирования отчёта.
Read-model — `AdminAccessAnalyticsService`.

## Метрики

| Показатель | Расчёт и значение |
|---|---|
| Подтверждённая аудитория | `subscriber` с непустым `telegram_id`, за всё время. |
| Новые | Та же аудитория с `created_at` внутри периода. |
| Открывали Mini App | `last_seen_at` внутри периода; не активность бота. |
| Начали trial / trial всего | `trial_used_at` в периоде / непустой за всё время. |
| Доступ | Текущие `preview`, `trialing`, исторический `paid`, `granted`, `expired` из entitlement и источника подписки. |
| Воронка | Зарегистрированы → trial → исторический платный доступ; проценты до одного знака, при нулевом делителе 0%. |
| Дневной график | Только регистрации и старты trial; retention и действия внутри поиска не реконструируются. |

Поле `paid` пока классифицирует только источник `telegram_stars`, оставленный
для совместимости. Рабочих продаж Stars нет; demo-гости не имеют Telegram ID
и в подтверждённую аудиторию не входят. Ручной `admin_grant` не считается
оплатой. После настоящей интеграции потребуется отдельно обновить коммерческие
метрики под нового провайдера.

## Границы и проверка

Интерфейс сообщает «Приём платежей пока не подключён». Выручка, прогнозы
и тестовые суммы не показываются. Экран не создаёт таблицы кампаний или
системных метрик; он читает существующие данные.

Проверять авторизацию, пустую базу, границы 7/30/90 дней, классификацию
источников, отсутствие персональных полей и выдуманной выручки. При смене
тарифов/платёжного источника проверять read-model вместе с доступом.
Общие UI-сценарии — [TESTING](TESTING.md), текущий выпуск —
[CURRENT-STATE](CURRENT-STATE.md).
