# Мой прайс: подбор тендеров и сравнение позиций

## Статус и пользовательский путь

Реализация PRO-01 от 28 октября 2026 года подготовлена для GitHub.
На VPS эта функция ещё не установлена. Для запуска нужна миграция
`2026_10_28_150000_create_price_catalogs` и сборка новой версии приложения.

Вход: **Профиль → Мой прайс** (`/catalog`). Для действующих Pro и Ultra
доступны загрузка Excel, ручное добавление/редактирование/удаление позиций,
предварительный подбор закупок и построчное сравнение. Basic видит пояснение
о доступе; данные каталога в ответ не включаются. Developer Mode применяет
фактически выбранный тариф. Истёкший доступ закрывает операции, сохраняя данные.

В карточке и рабочей области тендера для Pro / Ultra есть ссылка
«Сопоставить с моим прайсом». Каталог всегда личный: участник команды использует
свой прайс для разрешённой ему общей закупки, не читая прайсы коллег.

## Загрузка прайса

- Формат `.xlsx`, не более 5 МБ, до 500 позиций; читается первый лист.
- В первой непустой строке — заголовки. Обязателен только столбец «Название»
  (допустимы также «Наименование», «Товар», «Услуга», «Компетенция», `name`).
- Остальные столбцы: «Характеристики», «Цена», «Количество», «Единица»,
  «Регион». В коде перечислены дополнительные русские и английские варианты.
- Цена — рубли за указанную единицу; количество — доступный объём.
  Отсутствующее значение означает неизвестность, числовой ноль сохраняется.
- Поддерживаются десятичные точка и запятая, пробелы в числе. Цена — до двух,
  количество — до трёх знаков после запятой. Отрицательные числа отклоняются.
- Для услуг можно загружать компетенции: например, разработка сайта, SEO,
  поддержка, дизайн. Неизвестное количество оставляется пустым.
- Регион «Все регионы», «Вся Россия» или «Любой» разрешает любой известный
  регион закупки. Пустой регион остаётся неизвестным.

На странице есть Excel-шаблон с примерами. Пользователь должен заменить
демонстрационные позиции своими. Старый `.xls`, CSV, защищённые паролем файлы
и формулы не поддерживаются: формулы нужно заменить готовыми значениями.

Импорт сначала читает и проверяет весь файл. Только после этого транзакция
заменяет позиции. При ошибке строки, повреждённом файле или конфликте версии
старый прайс сохраняется. Для замены непустого каталога интерфейс требует
отметить явное подтверждение. Можно добавлять и править строки вручную.

Чтение реализовано через [OpenSpout 4.32.0](https://github.com/openspout/openspout/tree/v4.32.0).
Принимается только структура XLSX, проверяются размер распакованных данных
(до 32 МБ), число элементов архива (до 2000), пути внутри архива и отсутствие
DTD/ENTITY. В одном листе допускается до 20 столбцов. Загруженные файлы
обрабатываются временно; в БД сохраняются позиции и имя файла, не оригинал.

## Предварительный подбор тендеров

Кнопка «Найти тендеры под мой прайс» запускает проверку последних 300
доступных закупок собственных мониторингов, отсортированных по ID.
Показываются до 20 результатов, число проверенных карточек и найденных
совпадений; достижение ограничения обозначается явно.

Удалённые мониторинги, скрытые/архивные карточки пользователя, удалённые
личные заявки и закупки с известным прошедшим дедлайном исключаются.
Неизвестный дедлайн не считается подтверждением открытого приёма.

Слова из названий каталога сопоставляются с названием и первыми 4000 символами
описания закупки. Есть нормализация регистра, части окончаний, небольшой
словарь форм слова «сайт» и SEO. Общие слова закупок исключены. В результате
указаны связанные позиции прайса и совпавшие слова.

Это лексический подбор внутри уже доступной пользователю базы. Новые
мониторинги не создаются, внешние API и LLM не вызываются; полнота поиска
по всем площадкам и техническое соответствие не обещаются. Прайс не становится
общим поиском по чужим личным мониторингам. Для увеличения входящей выборки
пользователь настраивает свои мониторинги обычным способом.

## Подробное сравнение

Адрес: `/catalog/tenders/{id}`, с `?team_id={id}` для разрешённой команды.
Доступ к конкретному тендеру проверяется отдельно от тарифного доступа.

Источники пока не передают единый нормализованный перечень позиций.
Если спецификация не загружена, приложение проверяет только название
закупки и явно показывает, что полный перечень не передан. По названию
не восстанавливаются количество строк, состав заказа и процент его покрытия.

Пользователь может загрузить спецификацию в формате того же Excel-шаблона.
«Количество» в ней означает потребность заказчика; «Цена» не используется
для вывода о прибыльности. Галочка «Это полный перечень позиций закупки»
определяет подпись результата. Без неё выводы относятся к загруженной части.
Данные спецификации личные и не изменяют общую карточку источника.

Для каждой строки показываются до трёх кандидатов, совпавшие слова и проверки:

| Поле | Проверка |
|---|---|
| Название | Лексическое совпадение, без обещания семантической эквивалентности. |
| Характеристики | Наличие указанных слов и чисел; отсутствие данных требует уточнения. |
| Количество | Достаточность указанного остатка, с учётом нулевого значения. |
| Единица | Равенство или известные формы одной единицы; упаковки в штуки не пересчитываются. |
| Регион | Совпадение региона либо явно указанные в прайсе все регионы. |

При повторном использовании одной позиции проверяется суммарное количество
строк с согласованной единицей. Недостаточный или неизвестный общий запас
понижает автоматический результат до «Нужно уточнить». Это не резервирование
остатков между отдельными тендерами и не учёт текущих складских операций.

Счётчики:

- **Найдено:** предварительное совпадение названия и всех доступных проверок
  либо соответствие, явно подтверждённое пользователем.
- **Нужно уточнить:** кандидат есть, но условия отличаются, неизвестны
  или совпадение названия неполное.
- **Не найдено в каталоге:** подходящее название не найдено в этом прайсе
  либо пользователь сам зафиксировал отсутствие позиции.
- Отдельно показано, сколько найденных позиций подтверждено пользователем.

Пример с 18 явно загруженными строками: 12 предварительно найдены,
4 требуют уточнения, 2 не найдены в каталоге. Эти числа не генерируются
для карточки без спецификации. Цена позиции прайса показывается как введённая
пользователем; она не считается себестоимостью, прибылью или выигрышной ценой.

## Ручные решения и версии

Для строки можно выбрать любую свою позицию, указать «Подтверждаю
соответствие», «Нужно уточнить» или «Не найдено в моём каталоге», сохранить
пояснение либо вернуть автоподбор. Если при подтверждении есть отличия или
неизвестные условия, требуется пояснение пользователя.

Подтверждение помечено как пользовательское, а не как заключение площадки.
Оно хранится отдельно от исходного результата. Изменение прайса делает прежние
решения неактуальными, замена спецификации сбрасывает их. Изменение снимка
тендера также исключает прежние решения из действующего результата.

Все записи защищены проверкой версии. Для сравнения дополнительно сверяются
версия каталога и хеш данных тендера. Устаревшая вкладка получает HTTP 409
с предложением обновить данные. Операции сериализуются блокировкой пользователя;
при сохранении сравнения блокируется и проверяется актуальная карточка.

## Данные и эксплуатация

Миграция создаёт три таблицы:

- `price_catalogs`: один каталог на пользователя, версия и имя последнего файла.
- `price_catalog_items`: название, характеристики, цена, количество, единица,
  регион; связь с каталогом и каскадное удаление.
- `price_catalog_comparisons`: уникальная пара пользователь/тендер,
  личная спецификация, отметка полноты, ручные решения и версия.

Состав прайса и цены не пишутся в журнал. Событие `catalog.imported` содержит
только ID пользователя и число строк. Для дорогих запросов и изменений
настроены независимые ограничения частоты; загрузки и сохранения не расходуют
один общий счётчик друг друга.

PHP требует `dom`, `xmlreader`, `zip`; локальный PHP-образ их поддерживает,
в CI расширения перечислены явно. Для выпуска: резервная копия БД, сборка,
штатный запуск миграций, проверка `/catalog` и обеих тем интерфейса.

`deploy/php-uploads.ini` устанавливает PHP-пределы 10 МБ на файл и 12 МБ
на POST, чтобы не мешать пределам Laravel (5 МБ для прайса и 10 МБ
для существующих документов). Dockerfile копирует конфигурацию в образ,
локальный overlay монтирует тот же файл; после изменения нужен перезапуск
контейнера web. Настройка `upload_progress` не включается.

## Проверки

`PriceCatalogTest` проверяет доступ Pro/Ultra и отказ Basic/истёкшему доступу,
Developer Mode, изоляцию пользователей и команд, реальные XLSX и шаблон,
атомарность замены, числа и пустые значения, ограничение строк, повреждённые
архивы, формулы, DTD/ENTITY, конфликты версий, подбор услуг, ручные решения
и их устаревание, повторяющийся остаток и пример 12/4/2.

Проверки запускаются в отдельном SQLite `:memory:` test-контейнере.
Браузерная приёмка покрывает фактическую multipart-загрузку, ручное изменение
прайса, подбор, сравнение, сохранение решения и адаптивную вёрстку.

Проверено: 338 PHP-тестов / 3859 assertions, из них 28 сценариев каталога /
261 assertion; 11 JS-тестов, PHPStan, Pint, TypeScript/Vite, ESLint и Prettier.
Chromium: полный путь загрузки/редактирования/подбора/подтверждения и 16
сочетаний двух страниц, двух тем и ширин 320/390/760/1280 px. Проверена
фактическая смена темы, горизонтального переполнения и JS-ошибок нет.
Реальная multipart-загрузка файла 3 МБ принята; файл 6 МБ отклонён лимитом
Laravel 5 МБ без потери старого прайса. Синтетические браузерные данные удалены.
На физическом телефоне в Telegram эта версия отдельно не проверялась.
