# Проверка Mini App в Telegram и входа в рабочую ленту

Дата: 2 октября 2026 года. Production: Telegram Desktop на macOS, бот
`@RUTenderFinder_bot`, текущий аккаунт владельца. Изменения проверены также
локально в браузере при ширине 390 CSS px и на обычной ширине.

## Наблюдения в production до исправления

| Сценарий | Результат |
| --- | --- |
| Запуск через кнопку Open App | Приложение открылось и серверная Telegram-сессия подтвердилась. Первые секунды виден пустой фон загрузки. |
| Стартовый экран | Авторизованный пользователь попадал на рекламный экран с кнопкой «Открыть рабочее пространство». |
| Обзор после этой кнопки | Требовалась вторая кнопка «Открыть тендеры», хотя у пользователя уже есть активный доступ и совпадения. |
| Личная лента с совпадением | Вкладки «Лента / Участие / Аналитика / Календарь» находились после карточек внизу длинной страницы. |
| Экран участия, аналитика, календарь | Те же вкладки расположены сразу под заголовком, поэтому при переходе из ленты они визуально «прыгают». |
| Лента → карточка B2B-Center → заявка | Все три экрана открылись в настоящем Telegram. Бюджет, срок, объяснение совпадения и переход к участию видны. |
| Профиль | Экран и ссылка на обращения открылись; настройки уведомлений видны. |

## Исправление

- `/` направляет пользователя с активным доступом или trial прямо в `/tenders`.
  Для preview остаётся onboarding, для истёкшего доступа — обзор с действием
  продления. Гостевой маршрут остаётся информационным.
- Вкладки и выбор личного/командного пространства на заполненной ленте стоят
  в той же позиции, что и на экранах участия, аналитики и календаря.
- При пустой личной ленте без мониторинга главный поиск остаётся первым
  действием. Если мониторинг уже есть, рабочие вкладки находятся сверху.

Локальная проверка: после открытия `/` с активной тестовой сессией браузер
попал сразу в `/tenders`; в мобильной ширине вкладки видны вверху, а поле
«Найти тендеры» и кнопка остаются в первом экране. Для состояний preview,
expired и active добавлен серверный тест переходов.

## Источники: фактический охват

| Площадка | Код | Production / граница охвата |
| --- | --- | --- |
| Workspace.ru | Клиент RSS, парсер, очередь, импорт и matching | Включён. Только текущие карточки RSS, не полный архив. |
| B2B-Center | Публичный HTML-поиск по фразе, парсер, очередь и matching | Включён. Подтверждена только первая публичная страница. Карточка этого источника открыта в Telegram. |
| RosTender | API-клиент и polling шаблонов | Подключается отдельно по шаблону; production сообщает о задержке/квоте, новый ответ не подтверждён. |
| Сбербанк-АСТ | Клиент и парсер существуют | Выключен после тайм-аутов публичного реестра. |
| Росэлторг | Нет клиента и парсера | Нет подтверждённого доступного ответа для парсера; не интегрирован. |
| РТС-Тендер | Нет клиента и парсера | Нет подтверждённого доступного ответа для парсера; не интегрирован. |
| Прямой ЕИС | Удалён из runtime | Не является источником текущего поиска. |

Повторные обычные HTTPS-запросы с Mac 2 октября к `/torgi` и
`/procedures/search` Росэлторга, главной РТС-Тендер и Сбербанк-АСТ завершились
12-секундным тайм-аутом. Это ограничение текущего сетевого пути, а не
доказательство постоянной недоступности площадок. Предыдущая проверка с VPS
зафиксирована в `EXTERNAL-SOURCE-DISCOVERY.md`. Без рабочего публичного ответа
и проверенного формата нельзя безопасно реализовать парсер и обещать охват.

## Граница выполненной приёмки

Живой Telegram smoke покрывает чтение и переходы текущего аккаунта. Он не
подтверждает первый вход нового пользователя, согласия, платежи, командные
изменения, загрузку документов, создание нового тендера площадкой или
фактическую отправку нового Telegram-уведомления. Эти сценарии нельзя считать
прошедшими только по наличию экранов; перед публичным запуском нужны отдельные
контролируемые beta-сценарии с тестовыми учётными записями и событиями.
