# Ручная проверка UX/UI центра поддержки

Дата: 29 сентября 2026 года. Среда: локальный Docker runtime и браузер
Chromium в Codex; ширины 390 и 1280 CSS px. Использованы только синтетические
локальные обращения. Это отдельная проверка интерфейса, не замена серверных
feature-тестов и не приёмка в настоящем Telegram.

## Что проверено вручную

| Сценарий | Результат |
| --- | --- |
| Профиль подписчика | Вход «Мои обращения» виден сразу после имени; рядом понятно, где ждать ответ. |
| Профиль `super_admin` | «Центр поддержки» и число новых запросов видны до настроек уведомлений. |
| Новое обращение на 390 px | Тема, описание, отправка и пустое состояние помещаются без горизонтальной прокрутки; поля и кнопка имеют внутренние отступы. |
| Очередь на 390 px | Фильтры и «Обновить» не налезают друг на друга; карточки показывают статус, пользователя, ответственного и дату отдельными строками. |
| Переписка пользователя | Синтетическое обращение появилось в его списке; ответ поддержки виден только в его переписке, статус стал «В работе». Есть действие «Проверить ответ». |
| Обращение администратора на 390/1280 px | На мобильной ширине последовательный столбец; на desktop переписка и рабочие действия занимают две читаемые колонки. Причина, срок, подтверждение отзыва и журнал не выходят за границы карточек. |
| Права | Прямой переход подписчика на `/support/admin` вернул 403. |
| Ручной доступ | На локальной синтетической записи проверены экран выдачи, экран активного доступа, неактивная кнопка отзыва до подтверждения и запись в журнале. Серверные операции выдачи/отзыва/истечения проверены feature-тестами. |

## Найденные и исправленные дефекты

1. Все четыре экрана поддержки использовали `GlassCard` без внутренних
   отступов; заголовки и поля примыкали к краям. Добавлены системные отступы
   16/20 px и повторно осмотрены на 390 px.
2. Детальная карточка администратора на 1280 px растягивала одну форму на всю
   ширину. Введены две колонки с сохранением мобильного порядка.
3. В журнале событие пользователя ошибочно называло его администратором, а
   несколько записей сливались в строку. Исправлены подписи и разделение
   событий.
4. Ссылка на поддержку была в конце длинного профиля. Вход перенесён сразу
   под блок аккаунта; администратор видит отдельный вход в очередь.
5. В очереди дата разрывала строку ответственного. Метаданные разбиты на
   отдельные строки.

## Дополнительный осмотр: Developer Mode

29 сентября локальный профиль подписчика с синтетическим бессрочным Pro
проверен на 390 и 1280 px: бейдж «Про (Developer Mode)» и период «без даты
окончания» помещаются в карточку без наложения. Административное обращение с
тем же доступом проверено на обеих ширинах: тариф, срок, отзыв и журнал
читаются, мобильная колонка не переполняется. Во время осмотра найдены и
исправлены две неверные подписи: постоянный Pro назывался Basic, а системная
операция в журнале — удалённым участником. Синтетические записи удалены,
локальная конфигурация возвращена к исходной.

## Автоматические проверки

Автоматический контур перед коммитом: `php artisan test --compact` — 180
тестов, 1905 assertions; PHPStan без ошибок, Pint, ESLint, Prettier,
TypeScript/Vite build и `git diff --check` прошли. Эти результаты относятся к
локальному проверенному исходному коду. На VPS 29 сентября выпущен коммит
`d32716b`: миграция отмечена `Ran`, все сервисы запущены, PostgreSQL и Redis
отвечают, маршруты поддержки присутствуют, внешний `/health` вернул `ok`.
Первый внешний запрос с нового Mac завершился тайм-аутом, повторный прошёл;
работу из настоящего Telegram ещё предстоит проверить.

## Что проверить после релиза

Владелец должен открыть production Mini App именно из Telegram под обычным
пользователем и `super_admin`: создать обращение, увидеть его в очереди,
ответить, обновить переписку и подтвердить видимость ответа. Локальный
браузер не доказывает работу Telegram `initData`, реальную доставку и
production-права. Локальный осмотр проводился в светлой теме; тёмную тему
нужно осмотреть в Telegram при beta-приёмке. Ручная выдача доступа в
production дополнительно зависит
от опубликованных юридических документов и согласий конкретного пользователя.
