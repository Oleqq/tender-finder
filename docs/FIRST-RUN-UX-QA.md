# Первый вход и путь к мониторингу: проверка UX/UI

Дата: 30 сентября 2026 года. Среда: локальный Docker runtime, тестовая
серверная сессия и браузер Chromium. Проверены ширины 390 и 1280 CSS px.
Production проверен отдельно после релиза; реальный Telegram Mini App ещё
ожидает закрытую beta-приёмку.

## Задача

При первом входе обзор показывал пустое «Что требует внимания» раньше
действия, а лента без мониторингов показывала вкладки, поиск, статусы и
фильтры. Кнопка настройки оказывалась ниже первого экрана. В мастере пять
крупных переключателей шагов и карточка лимита отодвигали поля. Пустой
список ошибочно предлагал дождаться активации уже активного доступа.

## Что изменено

- Onboarding кратко объясняет результат и сразу ведёт к согласиям; три
  рекламные карточки удалены. Сами согласия и их серверный порядок сохранены.
- Обзор получает два признака из запросов только текущего пользователя:
  есть ли не удалённый мониторинг и есть ли сохранённые совпадения. По ним и
  статусу доступа выбирается один основной переход. Пустой список срочных
  действий больше не занимает экран. Назначенные действия остаются видимы.
- Дополнительная проверка различает активный и приостановленный мониторинг:
  обзор не называет паузу работающим поиском.
- Пустая личная лента без активных фильтров показывает один путь к мастеру
  или к уже созданному мониторингу. Командная лента и лента с данными
  сохраняют рабочие инструменты. Удалённый мониторинг не выводится в выборе
  фильтра.
- Ссылка из личной ленты теперь открывает клиентскую карточку тендера с
  бюджетом, сроком, причиной совпадения и переходом к участию. Раньше она
  вела на архивный операторский маршрут и давала подписчику 404.
- На первом экране мастера скрыты неактуальные лимит и пустой список.
  Пять кнопок шагов заменены прогрессом; назад можно вернуться отдельной
  кнопкой. Без доступного шаблона источника нельзя перейти к проверке.

## Автоматическая проверка

Feature-тесты проверяют изоляцию признаков обзора от чужого пользователя,
переходы «нет мониторинга → активен без совпадений → пауза → совпадения»,
исключение удалённых и чужих мониторингов из фильтра ленты и право открытия
клиентской карточки только владельцем совпадения. Полный набор: 188 тестов
и 2076 проверок; PHPStan, Pint, ESLint, Prettier, production build и
`git diff --check` пройдены перед дополнительным коммитом. Миграция базы не
нужна.

## Отдельная ручная проверка UI/UX

| Экран и состояние | 390 px | 1280 px |
| --- | --- | --- |
| Onboarding → согласия | Главная кнопка видна без прокрутки, порядок заголовка и текста ясен; оба согласия видны отдельно | Широкая версия без лишних карточек; юридический шаг остаётся отдельным |
| Обзор активного пользователя без мониторинга | Один CTA виден сразу, пустого блока задач нет, нижняя навигация не перекрывает кнопку | CTA и пояснение занимают читаемую колонку |
| Пустая личная лента | Один CTA вместо фильтров; поля и кнопка не обрезаны | Короткое сообщение и действие в рабочей колонке |
| Мониторинг на паузе, совпадений нет | Обзор показывает паузу, лента ведёт к проверке мониторинга | Та же иерархия |
| Есть совпадение → карточка → участие | Карточка открывается без 404; бюджет, срок и главное действие видны сразу | Карточка остаётся в читаемой колонке |
| Мастер: ниша → регион → бюджет → источник | Поля первого шага видны на первом экране; прогресс и кнопки не накладываются; переходы работают | Форма и прогресс выровнены; большие пустые блоки убраны |
| Источник без шаблонов | Ясное сообщение, «Далее» недоступно | Та же логика |
| Профиль → поддержка | Ссылка на помощь видна в начале профиля; форма обращения сохраняет отступы | Ранее проверено отдельно в SUPPORT-UI-QA |

В указанных экранах не обнаружено горизонтальной прокрутки, наложений на
нижнюю навигацию или обрезанной основной кнопки. Для осмотра паузы,
совпадения и карточки использованы синтетические локальные записи; после
проверки они удалены. Реальные источник и данные требуют beta-приёмки.

## Границы проверки

В локальной сессии нет шаблонов RosTender, поэтому мастер проверен до шага
источника без сохранения мониторинга и внешнего запроса. Согласия не
принимались ради визуального осмотра. Реальный путь «Telegram-вход → первый
RosTender-поиск → лента → уведомление» остаётся задачей beta-приёмки.

## Production smoke 30 сентября

Коммит `8a2e1ce` прошёл CI в обоих GitHub-репозиториях. Перед релизом копия
`postgres-20260930T104835Z.sql.gz` прошла `gzip -t`; SHA-256 архива исходников
совпал на Mac и VPS. Стандартный `sh deploy/vps-deploy.sh` выполнил сборку,
сообщил «Nothing to migrate» и запустил web, queue, scheduler, PostgreSQL,
Redis и Caddy. Web, PostgreSQL и Redis здоровы; все миграции имеют статус
`Ran`, права `.env.production` остались `600`. Внешний HTTPS `/health`
вернул `ok`, `/onboarding` — 200. На VPS защищённые маршруты обзора,
ленты, мониторингов и поддержки перенаправляют без сессии на onboarding.
Отдельные внешние TLS-соединения с Mac по-прежнему иногда завершаются
тайм-аутом; повторный запрос `/onboarding` получил 200. Визуальный
приём в настоящем Telegram и первый реальный поиск остаются открытыми.

## Дополнительный выпуск после проверки полного потока

Визуальный проход с одной синтетической карточкой обнаружил, что ссылка из
личной ленты открывала операторский legacy-маршрут и возвращала 404
подписчику. Исправление `5ce07c3` выпущено 30 сентября после зелёного CI
обоих репозиториев. Перед релизом копия
`postgres-20260930T111310Z.sql.gz` прошла `gzip -t`, SHA-256 нового архива
совпал. Стандартный скрипт завершил сборку, сообщил «Nothing to migrate»
и поднял все шесть сервисов. PostgreSQL принял соединение, Redis вернул
`PONG`, миграции имеют `Ran`, `.env.production` сохранил права `600`.
Внешний `/health` вернул `ok`; из VPS публичный onboarding ответил 200,
а новый маршрут карточки без сессии вернул ожидаемый редирект на onboarding.
Открытие карточки с настоящей Telegram-сессией остаётся для закрытой beta.
