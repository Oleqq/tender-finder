# Первый вход и путь к мониторингу: проверка UX/UI

Дата: 30 сентября 2026 года. Среда: локальный Docker runtime, тестовая
серверная сессия и браузер Chromium. Проверены ширины 390 и 1280 CSS px.
Production и реальный Telegram Mini App указаны отдельно после релиза.

## Задача

При первом входе обзор показывал пустое «Что требует внимания» раньше
действия, а лента без мониторингов показывала вкладки, поиск, статусы и
фильтры. Кнопка настройки оказывалась ниже первого экрана. В мастере пять
крупных переключателей шагов и карточка лимита отодвигали поля. Пустой
список ошибочно предлагал дождаться активации уже активного доступа.

## Что изменено

- Onboarding кратко объясняет результат и сразу ведёт к согласиям; три
  рекламные карточки удалены. Сами согласия и их серверный порядок сохранены.
- Обзор получает два признака из запросов только текущего пользователя:
  есть ли не удалённый мониторинг и есть ли сохранённые совпадения. По ним и
  статусу доступа выбирается один основной переход. Пустой список срочных
  действий больше не занимает экран. Назначенные действия остаются видимы.
- Пустая личная лента без мониторингов, совпадений и активных фильтров
  показывает один путь к мастеру. Командная лента и лента с данными сохраняют
  рабочие инструменты. Удалённый мониторинг не выводится в выборе фильтра.
- На первом экране мастера скрыты неактуальные лимит и пустой список.
  Пять кнопок шагов заменены прогрессом; назад можно вернуться отдельной
  кнопкой. Без доступного шаблона источника нельзя перейти к проверке.

## Автоматическая проверка

Feature-тесты проверяют изоляцию признаков обзора от чужого пользователя,
переходы «нет мониторинга → мониторинг без совпадений → совпадения», а также
исключение удалённых и чужих мониторингов из фильтра ленты. Полный набор:
187 тестов и 2032 проверок; PHPStan, Pint, ESLint, Prettier, production
build и `git diff --check` пройдены перед коммитом. Миграция базы не нужна.

## Отдельная ручная проверка UI/UX

| Экран и состояние | 390 px | 1280 px |
| --- | --- | --- |
| Onboarding → согласия | Главная кнопка видна без прокрутки, порядок заголовка и текста ясен; оба согласия видны отдельно | Широкая версия без лишних карточек; юридический шаг остаётся отдельным |
| Обзор активного пользователя без мониторинга | Один CTA виден сразу, пустого блока задач нет, нижняя навигация не перекрывает кнопку | CTA и пояснение занимают читаемую колонку |
| Пустая личная лента | Один CTA вместо фильтров; поля и кнопка не обрезаны | Короткое сообщение и действие в рабочей колонке |
| Мастер: ниша → регион → бюджет → источник | Поля первого шага видны на первом экране; прогресс и кнопки не накладываются; переходы работают | Форма и прогресс выровнены; большие пустые блоки убраны |
| Источник без шаблонов | Ясное сообщение, «Далее» недоступно | Та же логика |
| Профиль → поддержка | Ссылка на помощь видна в начале профиля; форма обращения сохраняет отступы | Ранее проверено отдельно в SUPPORT-UI-QA |

В указанных экранах не обнаружено горизонтальной прокрутки, наложений на
нижнюю навигацию или обрезанной основной кнопки. Проверка состояний обзора
с уже созданным мониторингом и совпадениями выполнена серверными тестами;
визуально эти состояния требуют реальных данных закрытой beta.

## Границы проверки

В локальной сессии нет шаблонов RosTender, поэтому мастер проверен до шага
источника без сохранения мониторинга и внешнего запроса. Согласия не
принимались ради визуального осмотра. Реальный путь «Telegram-вход → первый
RosTender-поиск → лента → уведомление» остаётся задачей beta-приёмки.
