# Проверка квоты RosTender и интерфейса мониторинга

Дата: 30 сентября 2026 года. Среда: локальный Docker runtime, SQLite для
автоматических тестов и браузер Chromium для ручного осмотра. Данные
мониторинга для визуальной проверки были синтетическими и удалены после неё.

## Причина изменения

Production-аудит показал, что после исчерпания дневной квоты активная лента
RosTender продолжала получать `quota_exhausted` при очередных часовых
запусках. Это не добавляло карточек, но создавало повторные задания и не
объясняло пользователю, когда ожидать следующую проверку.

## Что проверено автоматически

| Сценарий | Ожидаемый результат |
| --- | --- |
| Локальная квота исчерпана | HTTP-запрос не отправлен; записан `source_run`; следующая попытка — не раньше 00:05 следующего московского дня; dispatcher не ставит повторный job. |
| Удалённый 403 близко к полуночи | Следующая попытка учитывает и новый день, и полный обычный интервал. |
| Ручная кнопка при исчерпанной квоте | Ответ 422 с понятным текстом; задание не создано; пользовательский дневной счётчик не увеличен. |
| Ручная кнопка во время паузы после 403 | Запуск отклонён до расхода пользовательской попытки. |
| Статус мониторинга | Сообщение показывает ограничение источника, время следующей попытки и признак недоступности ручного запуска. |

Полный локальный набор перед коммитом: 185 тестов, 1972 assertions;
PHPStan, Pint, ESLint, Prettier, production build и `git diff --check` прошли.

## Ручная UX/UI-проверка

На локальном тестовом пользователе создан один мониторинг с синтетическим
отказом квоты и следующей попыткой в 00:05 по Москве. На ширинах 390 и
1280 CSS px осмотрены карточка, иерархия заголовков, сообщение, три даты,
кнопки и нижняя навигация. Горизонтальной прокрутки, наложений и текста у
края карточки не найдено. В первоначальном экране была противоречивая фраза
«Нажмите „Проверить сейчас“» при исчерпанной квоте. Её заменили описанием
состояния источника, а ручную кнопку во время паузы сделали неактивной с
подписью «Проверка позже». Повторный осмотр подтвердил видимое время
следующей попытки и корректные отступы на обеих ширинах.

Локальный осмотр не подтверждает поведение в настоящем Telegram Mini App:
там ещё нужно проверить тему, локальное время, нажатия и восстановление
опроса после обновления квоты. Production smoke и результаты полного набора
проверок дополняются после выпуска.
