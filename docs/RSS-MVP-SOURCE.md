# ЕИС RSS: источник local MVP

## Статус

ЕИС `zakupki.gov.ru` — единственный подключённый источник локального MVP.
Пользователь вручную запускает поиск; приложение формирует RSS-URL
расширенного поиска по фразе или принимает RSS-ссылку, созданную в ЕИС для
расширенных условий. Это не API ЕИС, не полный каталог и не автоматический
мониторинг.

Параметры встроенной формы сверены с публичным
[расширенным поиском ЕИС](https://zakupki.gov.ru/epz/order/extendedsearch/search.html),
а ОКПД2 выбирается через публичный справочник этого же портала. Приложение не
передаёт в браузер сырой ответ справочника.

Фразу, проверенные условия источника, глубину и разрешённую RSS-ссылку можно
сохранить как именованный запрос. Кнопка «Запустить сейчас» повторяет тот же
ручной путь и записывает отдельный персональный снимок результата со
счётчиками и причинами совпадения. Режим сопоставления и минус-слова также
сохраняются. Кнопка не меняет статус ленты и не создаёт фоновую задачу.

## Что делает приложение

- принимает только HTTPS-URL `zakupki.gov.ru` и разрешённый путь расширенного
  поиска;
- использует строгую TLS-проверку, таймаут и лимит размера XML;
- по нажатию получает одну, три, пять или до десяти RSS-страниц последовательно;
- добавляет в автоматический RSS-запрос только проверенные условия: 44‑ФЗ,
  223‑ФЗ, НМЦК, дату публикации и этапы «Подача заявок», «Работа комиссии»,
  «Закупка завершена», «Закупка отменена»;
- поддерживает проверенные признаки блока «Дополнительная информация»:
  совместную закупку, размещение обособленным подразделением, бюджет Союзного
  государства, создание представителем заказчика и закупку у СМП и СОНО;
- передаёт до пяти регионов как пары служебных параметров КЛАДР
  `delKladrIds`/`delKladrIdsCodes` и до пяти позиций ОКПД2 как пары
  `okpd2Ids`/`okpd2IdsCodes`; для ОКПД2 можно отдельно включить
  `okpd2IdsWithNested`;
- игнорирует невалидные ссылки элементов, не переходя по ним;
- удаляет служебный блок «Параметры поиска» из проверки релевантности;
- после ответа ЕИС проверяет предмет закупки по одному из режимов: все слова,
  любое слово или точная фраза;
- исключает карточку, если её предмет содержит одно из заданных минус-слов или
  минус-фраз;
- сохраняет структурированную причину совпадения и показывает её в текущей
  выдаче и истории;
- извлекает предмет закупки, тип процедуры, закон, НМЦК и заказчика только
  если они переданы RSS;
- дедуплицирует тендеры по номеру извещения или канонической ссылке.

RSS может не содержать регион, дедлайн, документы или полный текст. Эти поля
не придумываются: карточка показывает только данные источника и внешнюю
ссылку на ЕИС.

Режим релевантности и минус-слова являются локальным постфильтром. Они не
меняют контракт RSS и не могут вернуть карточку, которую сам поиск ЕИС не
включил в ответ. Служебный блок «Параметры поиска» не участвует ни в
положительном совпадении, ни в проверке исключений.

Регион не принимается произвольным текстом: интерфейс предлагает встроенный
список субъектов из второго уровня публичного справочника КЛАДР ЕИС и хранит
только 11-значный код. ОКПД2 ищется сервером через публичный справочник ЕИС;
браузер получает только безопасные `id`, `code` и `name`, после чего
сохранённый запрос хранит выбранную пару служебного ID и кода. Для обоих
фильтров действует лимит ЕИС — не более пяти позиций. Ручная RSS-ссылка
полностью заменяет встроенные поля, чтобы не смешивать два разных набора
параметров.

Автоматический запрос требует хотя бы один этап закупки. Признаки
«Дополнительной информации» передаются в ЕИС как независимые условия; их
применимость к 44‑ФЗ и 223‑ФЗ подписана в интерфейсе. И этапы, и признаки
сохраняются в именованном запросе и восстанавливаются при ручном повторном
запуске. То же относится к регионам, ОКПД2 и признаку вложенных кодов.

Для сохранённого запроса доступны последние двадцать персональных снимков.
«Только новые» вычисляется локально как разница ID карточек выбранного снимка
и непосредственно предыдущего снимка этого же пользователя и запроса. Это не
новизна во всей ЕИС и не фоновый мониторинг; в первом запуске новыми считаются
все его карточки.

## Границы

`RSS_LIVE_POLLING_ENABLED=false`. Новый или сохранённый ручной поиск не создаёт
активную ленту, задачу мониторинга или Telegram-уведомление. Максимум десять страниц за запрос
защищает источник от бесконтрольного обхода, но не означает полноту поиска
ЕИС. В каждом запуске интерфейс показывает фактическое число проверенных
страниц и карточек.

Не допускаются отключение TLS, `curl -k`, `verify=false`, CAPTCHA-обход,
cookies, прокси-ротация и HTML-скрапинг «на удачу».

## Проверка и отладка

Обычный путь — кнопка local MVP. Диагностическая команда делает один
allowlisted запрос и выводит только безопасные агрегаты:

```powershell
docker compose -f compose.local.yml -f compose.local.dev.yml run --rm cli php artisan tenders:probe-eis-rss '<RSS URL>'
```

Не записывайте в Git URL с фильтрами, ответ RSS, cookies, секреты или
содержимое живых закупок. Для локальной цепочки сертификатов см.
[`deploy/local-ca/README.md`](../deploy/local-ca/README.md).
