# Проверка новых источников: Росэлторг и РТС-Тендер

> Проверено повторно 1 октября 2026 года. Это запись исследования и release
> gate, а не разрешение получать данные с площадок.

## Результат

В публично найденных материалах Росэлторга доступна открытая поисковая витрина
закупок, однако опубликованное API относится к отдельному сервису электронного
документооборота и тарифному доступу, а не к выгрузке реестра закупок. Для
РТС-Тендер в публично доступной документации не найден подтверждённый API или
специальный RSS/экспорт для такого мониторинга. Ни одна из этих находок не
даёт TenderFinder права на автоматический сбор или распространение карточек.

Поэтому на дату проверки **не добавлены** HTTP-клиенты, HTML-парсеры, polling,
переменные окружения или production-флаги для этих площадок. Не используется
авторизация, чужие учётные записи, cookies, CAPTCHA или обход сетевых
ограничений.

## Что подтверждено первичными материалами

- На [открытой витрине Росэлторга](https://www.roseltorg.ru/torgi) есть поиск
  закупок и публичные карточки процедур.
- [Документация Росэлторг.ЭДО](https://www.roseltorg.ru/_flysystem/webdav/2022/12/29/RP_edo_v18.pdf)
  описывает API для создания документов в отдельном ЭДО-сервисе на тарифе
  «Корпоративный +»; это не основание использовать его для тендерной ленты.
- Открытая часть площадки и закрытые разделы различаются в
  [регламенте Росэлторга](https://www.roseltorg.ru/_flysystem/webdav/2024/01/17/rp_fkr_15012024.pdf).

Публичное обнаружение страниц не заменяет письменного подтверждения оператора
площадки. Условия РТС-Тендер и пределы допустимого автоматизированного доступа
должны быть подтверждены именно для планируемого сценария до написания кода.

## Повторная проверка 1 октября

- [Росэлторг сообщает о сохранённом поиске](https://www.roseltorg.ru/knowledge_db/systems/notes/na-roseltorg-poyavilas-vozmozhnost-sokhranyat-parametry-poiska)
  в открытой части сайта. Это пользовательская функция сайта; сообщение не
  описывает разрешённый для TenderFinder API или экспорт закупок.
- [РТС-Академия пишет](https://academy.rts-tender.ru/supplier/article/goszakupki%20s%20nulya_instrukciya_dlya_novichkov),
  что человек может искать закупки на РТС-Тендер без регистрации. В статье
  нет условий автоматического доступа, квот или разрешения показывать
  полученные карточки пользователям другого сервиса.
- В production TenderFinder сейчас активна одна лента `rostender`. Клиенты
  Сбер АСТ, Workspace.ru и B2B-Center есть в коде, но выключены в production.
  Их наличие не подтверждает права на сбор с Росэлторга или РТС-Тендер.

Общий контур проекта уже готов к подключению разрешённого источника:
`source_feeds` и `source_feed_items`, импорт с дедупликацией, очередь,
планировщик, сопоставление с личными мониторингами, уведомления и фильтры
личной/командной ленты. После получения контракта не требуется проектировать
вторую систему хранения или отдельный пользовательский поиск.

## Необходимое owner/юридическое решение

Для **каждой** площадки получить и сохранить вне репозитория ответ оператора:

1. разрешён ли автоматизированный доступ к конкретному публичному реестру;
2. какой именно endpoint или экспорт разрешён, его квота, User-Agent и
   правила кэширования;
3. разрешено ли хранить и показывать карточки пользователям TenderFinder;
4. можно ли проверять endpoint из production VPS.

После положительного ответа разработчик фиксирует только не-секретные детали
контракта в отдельном source-документе, добавляет allowlist URL, изолированный
клиент, fixtures, интеграционные тесты и выключенный по умолчанию флаг. До
этого следующий шаг — не код, а получение разрешения владельцем.

## Вопросы оператору для письменного ответа

Для каждой площадки владелец может отправить один и тот же запрос от имени
TenderFinder:

> Мы разрабатываем сервис мониторинга закупок для авторизованных пользователей.
> Уточните, пожалуйста, разрешаете ли вы автоматически получать открытые
> карточки процедур с вашего ресурса, сохранять их в нашей базе, показывать
> пользователям сервиса и отправлять им уведомления со ссылкой на первоисточник.
> Если да, укажите разрешённый API/экспорт и конкретный endpoint, способ
> доступа, лимиты и частоту запросов, требуемый User-Agent, срок хранения и
> правила обновления/удаления карточек. Допустимы ли запросы с нашего VPS и
> нужен ли отдельный договор или тариф? Просим ответить отдельно для
> публичных и требующих авторизации данных.

Полученный ответ хранится вне Git и передаётся разработке без ключей и иных
секретов. Частичный ответ не снимает gate для неоговорённых видов данных.
