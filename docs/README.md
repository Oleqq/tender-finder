# Tender Finder: понятный план старта

Этот документ - упрощённая версия исходного ТЗ. Он нужен как рабочая карта: что делать, в каком порядке и зачем. Исходное ТЗ остаётся главным документом с требованиями и не заменяется этим файлом.

## Что мы делаем

Tender Finder - веб-сервис поиска тендеров с интерфейсом Telegram Mini App, обычным Telegram-ботом и закрытой админ-панелью. Пользователь управляет поиском в Mini App, а бот присылает уведомления, открывает приложение и остаётся доступным через команды.

Пользователь должен суметь:

1. Запустить бота или открыть Mini App, принять оферту и политику конфиденциальности.
2. Бесплатно пользоваться полным функционалом 72 часа.
3. Создать до трёх поисковых запросов: например, «разработка Telegram-бота», Москва, бюджет от 100 000 ₽.
4. Получать подходящие закупки из ЕИС быстро, целевой предел - за 30 минут после публикации.
5. После trial оплатить тариф и продолжить работу без потери запросов.

Администратор должен управлять пользователями, запросами, источниками, платежами и подписками через браузерную админ-панель. У владельца проекта будет внутренний бесплатный доступ без обхода логики платежей: он оформляется как отдельный тип доступа в системе.

Первый релиз не обязан искать всё. Его задача - надёжно работать с ЕИС, показать ценность пользователю и принять первую оплату.

## Что выбрать: Laravel и React

Выбираем **PHP 8.3 + Laravel 11/12 для backend и React + TypeScript для frontend**.

Почему это лучше именно в этом проекте:

- PHP и Laravel - ваша наиболее сильная backend-специализация: у вас есть практика с Laravel, React, MySQL, деплоем и поддержкой production-проектов.
- React нужен с первого дня: он будет интерфейсом Mini App для клиентов и браузерной админ-панелью для владельца.
- Laravel уже даёт очереди, планировщик, миграции, вебхуки, валидацию, логи, тесты и удобную работу с платежами. Это уменьшает количество новых решений в MVP.
- Бот, парсер, рассылки, trial и платежи - в основном серверная бизнес-логика, а не задача, где JavaScript заметно выигрывает.
- Для Telegram, ЮKassa, PostgreSQL и Redis в PHP есть зрелые библиотеки и понятный способ развернуть всё через Docker.

Node.js как отдельный backend не нужен: React собирается Vite внутри Laravel-проекта, а Laravel отдаёт API, проверяет Telegram-авторизацию и обслуживает webhook. Это даёт полноценные frontend и backend без двух серверных приложений и дублирования логики.

## Рекомендуемый MVP-стек

| Зона | Выбор |
|---|---|
| Backend и API | PHP 8.3, Laravel |
| Frontend | React, TypeScript, Vite, Inertia.js |
| Telegram | Mini App на домене + Bot API через webhook |
| База данных | PostgreSQL 16 |
| Очереди и кэш | Redis + Laravel Horizon/queues |
| Фоновые задачи | Laravel Scheduler + очереди |
| Платежи MVP | ЮKassa, вебхуки с проверкой подписи |
| Сбор ЕИС для закрытого MVP | RSS расширенного поиска ЕИС, серверный polling и отдельный адаптер источника |
| Сбор ЕИС после MVP | Сервисы отдачи информации ЕИС (СОИ) или лицензированный поставщик данных |
| Запуск | Docker Compose, Nginx, HTTPS, VPS в РФ, домен проекта |
| Админка | React-интерфейс в Laravel, входит в MVP |

Не начинаем с AI-скоринга, Telegram Stars, коммерческих площадок и реферальной программы: это следующий этап после доказанного MVP. Минимальная полноценная админ-панель и Mini App нужны уже в MVP.

## Как будут работать Mini App, бот и админка

- **Mini App** - основной личный кабинет клиента: список тендеров, создание и редактирование запросов, настройки уведомлений, подписка.
- **Бот** - точка входа и канал уведомлений. Команды вроде `/start`, `/results` и `/subscribe` открывают нужный экран Mini App; важные действия остаются доступны через кнопки в сообщениях.
- **Админка** - отдельный защищённый раздел того же домена. В ней можно искать пользователей, смотреть их подписки и платежи, выдавать/отзывать внутренний доступ, просматривать запросы и состояние импорта, отправлять рассылки.

Все три интерфейса используют один backend и одну базу данных. Это важно: изменение подписки в админке сразу меняет доступ в Mini App и в боте.

## С чего начать

### 1. Закрыть внешние зависимости

До программирования нужны:

- зарегистрированный Telegram-бот и его токен;
- несколько вручную проверенных RSS-лент ЕИС для тестов; доступ к СОИ продолжаем запрашивать параллельно;
- магазин ЮKassa на ИП, ключи тестовой среды и настройка чеков 54-ФЗ;
- ссылки на утверждённые оферту и политику конфиденциальности;
- VPS в РФ, домен с HTTPS и отдельный служебный Telegram-чат для алертов.

Без СОИ ЕИС и тестовой ЮKassa можно запустить закрытый MVP на RSS. Для массового запуска всё равно нужно подтвердить официальный канал данных или заключить договор с поставщиком.

### 2. Поднять пустой, но запускаемый проект

Создать Laravel-проект с React/TypeScript, Docker Compose, `.env.example`, PostgreSQL, Redis и базовый CI. Затем сделать `/health`, тестовый webhook Telegram и пустой Mini App, открывающийся по HTTPS. На этом шаге бот должен ответить на `/start`, а проект - запускаться одной командой локально.

### 3. Сделать путь одного пользователя целиком

Не распыляйтесь на все команды сразу. Пройдите один путь от начала до конца:

`/start` → открытие Mini App → согласие → trial → создание одного запроса → загрузка тестового тендера → уведомление → завершение trial → экран оплаты → активация после webhook ЮKassa.

Когда этот маршрут работает, продукт уже можно показывать тестовым пользователям.

### 4. Подключить реальные данные и автоматизацию

Добавьте серверный RSS polling ЕИС, дедупликацию тендеров, матчинг по фильтрам, очередь уведомлений и защиту от спама. После этого можно запускать закрытое тестирование.

### 5. Проверить перед первым реальным платежом

Нужны тесты trial, лимитов, матчей и платежных webhook; проверка чека ЮKassa; резервное копирование БД; логи без персональных данных; ручной чек-лист из ТЗ.

## Что войдёт в MVP

- регистрация по Telegram ID с согласием на документы;
- trial на 72 часа и напоминания за 24 и 3 часа;
- до трёх запросов с ключевыми словами, минус-словами, регионом и диапазоном НМЦК;
- RSS-импорт извещений ЕИС, дедупликация и поиск совпадений;
- уведомления в Telegram и антиспам: максимум 20 карточек в час;
- paywall после trial: запросы сохраняются и замораживаются;
- тарифы «Базовый» 990 ₽ и «Про» 2 990 ₽, оплата через ЮKassa;
- отмена подписки с доступом до конца оплаченного периода;
- React Mini App: тендеры, запросы, настройки и подписка;
- React-админка: пользователи, подписки, платежи, выдача внутреннего доступа, запросы, источники и журнал действий.

## Что отложить

| После MVP | Причина |
|---|---|
| Дайджест, ОКПД2 и типы закупок | План v1.1, не мешают первой проверке спроса |
| Коммерческие источники и ЭТП | Нужны отдельные соглашения, адаптеры и поддержка |
| AI-скоринг | Дорогая и сложная функция, сначала важнее точный базовый матчинг |
| Telegram Stars, годовые планы, рефералы | Не нужны для первой оплаты через ЮKassa |

## Как работать одному

Работайте короткими завершёнными кусками. Каждый кусок должен иметь понятный результат, тест и запись в `PROGRESS.md`.

1. Создать ветку под задачу.
2. Сделать минимальную законченную функцию.
3. Проверить её автоматически и вручную.
4. Обновить документацию и журнал прогресса.
5. Коммитить только то, что относится к задаче.

Перед любым коммитом проверьте, что в новых и изменённых файлах нет упоминаний внутренних инструментов разработки. Коммиты и публичная документация должны описывать только продукт и технические изменения.

## Ориентир по срокам

План из ТЗ: три недели на MVP, ещё две на v1.1 и три-четыре на v2.0. Для одного разработчика разумнее считать это ориентиром, а не обещанием: сначала завершить MVP по критериям приёмки, затем уточнить сроки по фактической скорости импорта ЕИС и интеграции ЮKassa.

Подробная техническая разбивка находится в [TECHNICAL-PLAN.md](TECHNICAL-PLAN.md), спецификация временного RSS-источника - в [RSS-MVP-SOURCE.md](RSS-MVP-SOURCE.md), а текущее состояние - в [PROGRESS.md](PROGRESS.md).
