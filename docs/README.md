# Tender Finder: понятный план старта

Этот документ - упрощённая версия исходного ТЗ. Он нужен как рабочая карта: что делать, в каком порядке и зачем. Исходное ТЗ остаётся главным документом с требованиями и не заменяется этим файлом.

## Что мы делаем

Tender Finder - Telegram-бот по подписке, который ищет новые тендеры под критерии пользователя и присылает подходящие варианты в Telegram.

Пользователь должен суметь:

1. Запустить бота и принять оферту и политику конфиденциальности.
2. Бесплатно пользоваться полным функционалом 72 часа.
3. Создать до трёх поисковых запросов: например, «разработка Telegram-бота», Москва, бюджет от 100 000 ₽.
4. Получать подходящие закупки из ЕИС быстро, целевой предел - за 30 минут после публикации.
5. После trial оплатить тариф и продолжить работу без потери запросов.

Первый релиз не обязан искать всё. Его задача - надёжно работать с ЕИС, показать ценность пользователю и принять первую оплату.

## Что выбрать: PHP или JavaScript

Выбираем **PHP 8.3 + Laravel 11/12**.

Почему это лучше именно в этом проекте:

- PHP и Laravel - ваша наиболее сильная backend-специализация: у вас есть практика с Laravel, React, MySQL, деплоем и поддержкой production-проектов.
- Laravel уже даёт очереди, планировщик, миграции, вебхуки, валидацию, логи, тесты и удобную работу с платежами. Это уменьшает количество новых решений в MVP.
- Бот, парсер, рассылки, trial и платежи - в основном серверная бизнес-логика, а не задача, где JavaScript заметно выигрывает.
- Для Telegram, ЮKassa, PostgreSQL и Redis в PHP есть зрелые библиотеки и понятный способ развернуть всё через Docker.

JavaScript/Node.js тоже подходит, особенно если важна одна технология на backend и React-админке. Но в данной ситуации он добавит обучение и не даст существенного преимущества. JavaScript стоит оставить для будущей веб-админки на React или Inertia.

## Рекомендуемый MVP-стек

| Зона | Выбор |
|---|---|
| Backend и webhook Telegram | PHP 8.3, Laravel |
| Telegram | Bot API через PHP SDK, webhook вместо постоянного polling |
| База данных | PostgreSQL 16 |
| Очереди и кэш | Redis + Laravel Horizon/queues |
| Фоновые задачи | Laravel Scheduler + очереди |
| Платежи MVP | ЮKassa, вебхуки с проверкой подписи |
| Сбор ЕИС | официальный API в приоритете; отдельный адаптер источника |
| Запуск | Docker Compose, Nginx, HTTPS, VPS в РФ |
| Админка v1.1 | Laravel + Inertia/React либо Filament |

Не начинаем с AI-скоринга, Telegram Stars, коммерческих площадок, реферальной программы и сложной админки: это следующий этап после доказанного MVP.

## С чего начать

### 1. Закрыть внешние зависимости

До программирования нужны:

- зарегистрированный Telegram-бот и его токен;
- подтверждение способа получения данных ЕИС: документация API, тестовый доступ и допустимые лимиты;
- магазин ЮKassa на ИП, ключи тестовой среды и настройка чеков 54-ФЗ;
- ссылки на утверждённые оферту и политику конфиденциальности;
- VPS в РФ, домен и отдельный служебный Telegram-чат для алертов.

Без API ЕИС и тестовой ЮKassa можно сделать каркас, но нельзя честно принять MVP.

### 2. Поднять пустой, но запускаемый проект

Создать Laravel-проект, Docker Compose, `.env.example`, PostgreSQL, Redis и базовый CI. Затем сделать `/health` и тестовый webhook Telegram. На этом шаге бот должен ответить на `/start`, а проект - запускаться одной командой локально.

### 3. Сделать путь одного пользователя целиком

Не распыляйтесь на все команды сразу. Пройдите один путь от начала до конца:

`/start` → согласие → trial → создание одного запроса → загрузка тестового тендера → уведомление → завершение trial → страница оплаты → активация после webhook ЮKassa.

Когда этот маршрут работает, продукт уже можно показывать тестовым пользователям.

### 4. Подключить реальные данные и автоматизацию

Добавьте плановый импорт ЕИС, дедупликацию тендеров, матчинг по фильтрам, очередь уведомлений и защиту от спама. После этого можно запускать закрытое тестирование.

### 5. Проверить перед первым реальным платежом

Нужны тесты trial, лимитов, матчей и платежных webhook; проверка чека ЮKassa; резервное копирование БД; логи без персональных данных; ручной чек-лист из ТЗ.

## Что войдёт в MVP

- регистрация по Telegram ID с согласием на документы;
- trial на 72 часа и напоминания за 24 и 3 часа;
- до трёх запросов с ключевыми словами, минус-словами, регионом и диапазоном НМЦК;
- импорт извещений ЕИС, дедупликация и поиск совпадений;
- уведомления в Telegram и антиспам: максимум 20 карточек в час;
- paywall после trial: запросы сохраняются и замораживаются;
- тарифы «Базовый» 990 ₽ и «Про» 2 990 ₽, оплата через ЮKassa;
- отмена подписки с доступом до конца оплаченного периода;
- минимальная служебная страница состояния: пользователи, платежи, ошибки импорта.

## Что отложить

| После MVP | Причина |
|---|---|
| Дайджест, ОКПД2 и типы закупок | План v1.1, не мешают первой проверке спроса |
| Полноценная админка и личный кабинет | Сначала достаточно служебного интерфейса |
| Коммерческие источники и ЭТП | Нужны отдельные соглашения, адаптеры и поддержка |
| AI-скоринг | Дорогая и сложная функция, сначала важнее точный базовый матчинг |
| Telegram Stars, годовые планы, рефералы | Не нужны для первой оплаты через ЮKassa |

## Как работать одному

Работайте короткими завершёнными кусками. Каждый кусок должен иметь понятный результат, тест и запись в `PROGRESS.md`.

1. Создать ветку под задачу.
2. Сделать минимальную законченную функцию.
3. Проверить её автоматически и вручную.
4. Обновить документацию и журнал прогресса.
5. Коммитить только то, что относится к задаче.

Перед любым коммитом проверьте, что в новых и изменённых файлах нет упоминаний внутренних инструментов разработки. Коммиты и публичная документация должны описывать только продукт и технические изменения.

## Ориентир по срокам

План из ТЗ: три недели на MVP, ещё две на v1.1 и три-четыре на v2.0. Для одного разработчика разумнее считать это ориентиром, а не обещанием: сначала завершить MVP по критериям приёмки, затем уточнить сроки по фактической скорости импорта ЕИС и интеграции ЮKassa.

Подробная техническая разбивка находится в [TECHNICAL-PLAN.md](TECHNICAL-PLAN.md), а текущее состояние - в [PROGRESS.md](PROGRESS.md).
