# Trial → paid: состояние интерфейса и контракт

## Действующий путь в Mini App

`AccessService::snapshotFor()` остаётся единственным источником доступа. Общий Inertia `auth.access` содержит `state`, `ends_at`, `active_query_limit` и `mode`. Для истёкшего доступа сервер теперь возвращает дату последнего завершённого entitlement. `/plans` получает отдельное `purchase = { availability: 'unavailable', plans: [], checkout: null }` независимо от флагов провайдера.

- `preview`: приглашение принять документы и начать 72-часовой триал.
- `trialing`, больше 24 часов: спокойный статус и оставшееся время.
- `trialing`, 24 часа или меньше: предупреждение на обзоре и на экране доступа. Время вычисляется по серверному `ends_at`; открытая страница перепроверяет сервер после срока.
- `expired`: мониторинги остановлены серверным lifecycle; сохранённые настройки и данные остаются. Видны дата предыдущего периода, мониторинги и поддержка.
- `active`: реальные срок и лимит из entitlement; доступ владельца сохраняет свой режим.

Переход «Оплатил, но доступа нет» открывает пустую форму поддержки с категорией `access` и подсказкой указать время/идентификатор заказа без данных карты. Это обращение **не** меняет entitlement.

## Подготовленный внешний интерфейс

`ExternalCheckoutJourney` — отдельный React-компонент для самостоятельного внешнего канала. Он не импортируется в Mini App и не имеет публичного маршрута. Контракт `ExternalPurchaseState` и `PurchasePlan` требует серверные название, описание, сумму в копейках, валюту RUB, срок, лимит и ссылку на условия. Пустой каталог показывает отсутствие условий без тестовых цен. Состояния заказа: выбор плана, `preparing`, `awaiting_payment`, `canceled`, `failed`, `access_pending`, `succeeded`. Действия передаются контейнером будущего внешнего сайта; сейчас обработчиков создания заказа и оплаты нет.

`ExternalCheckout` содержит `succeeded` только вместе с серверным `Access` в состоянии `active`. Будущий адаптер обязан возвращать это состояние лишь после сверки `succeeded` у провайдера и выдачи entitlement. Возврат браузера с `return_url`, клиентский callback и любой входящий параметр `status` не дают доступ. Для `access_pending` пользователь может перепроверить статус или обратиться в поддержку.

## Перед включением внешнего канала

Нужны утверждённые продавец, тип покупателя, цена/срок/лимит каждого плана, условия разовой покупки, чеки, возвраты, связка покупателя с аккаунтом и юридическая проверка размещения. Затем нужны отдельные модели заказа и событий, серверный каталог, API создания заказа с идемпотентностью, проверенный webhook, сверка платежа и идемпотентная выдача доступа. Только после этого можно подключить обработчики и маршрут **отдельного внешнего сайта**. Нельзя использовать `YooKassaClient` как доказательство завершённой интеграции. В Mini App не добавлять внешнюю кнопку оплаты без согласования с правилами Telegram; для цифровой услуги внутри Telegram действует Stars: https://core.telegram.org/bots/payments-stars.
