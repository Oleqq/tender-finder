# Локальный Docker MVP

Этот контур предназначен для разработки и ручной проверки ЕИС. Он не является
VPS, публичным SaaS, Telegram-ботом или постоянным мониторингом.

## Запуск

1. Установите Docker Desktop.
2. Создайте локальный `deploy/local-runtime.env` из
   `deploy/local-runtime.example.env`. Не открывайте и не добавляйте его в Git.
3. Выполните:

```powershell
docker compose -f compose.local.yml -f compose.local.dev.yml build
docker compose -f compose.local.yml -f compose.local.dev.yml --profile ops run --rm migrate
docker compose -f compose.local.yml -f compose.local.dev.yml up -d web queue scheduler vite
docker compose -f compose.local.yml -f compose.local.dev.yml ps
```

Приложение: `http://127.0.0.1:8080`.
Рабочее место MVP: `http://127.0.0.1:8080/local/mvp-operator`.
Локальный full-access вход: `http://127.0.0.1:8080/local/mvp-subscriber`.
Vite HMR: `http://127.0.0.1:5173`.

В dev-overlay включён `LOCAL_MVP_FULL_ACCESS_ENABLED=true`: local-вход и
подтверждённый Telegram-вход в `local/testing` получают роль `super_admin` и
активный доступ без consent, trial и ожидания активации. Лимит локального
доступа задаёт `LOCAL_MVP_FULL_ACCESS_QUERY_LIMIT` (по умолчанию 20). Это
режим быстрой UI-приёмки, а не подписка, не платёж и не production-модель.
На Railway/VPS флаг не включать: там роли, consent и доступ должны вернуться к
обычному серверному сценарию.

## Ручной поиск ЕИС

1. Откройте local MVP.
2. Введите поисковую фразу без персональных и секретных данных.
3. Выберите правило локальной релевантности: все слова, любое слово или точная
   фраза. При необходимости укажите до 20 минус-слов или фраз через запятую.
   Эти правила применяются только к карточкам, уже возвращённым RSS-поиском
   ЕИС, и не расширяют исходную выдачу портала.
4. При необходимости задайте 44‑ФЗ/223‑ФЗ, НМЦК, период публикации и этапы
   закупки. Для автоматически сформированного запроса должен быть выбран хотя
   бы один этап. В раскрывающемся блоке «Дополнительная информация» доступны
   проверенные признаки ЕИС: совместная закупка; размещение обособленным
   подразделением; бюджет Союзного государства; создание представителем
   заказчика; закупка у СМП и СОНО. Подписи в интерфейсе показывают применимость
   к 44‑ФЗ или 223‑ФЗ. Все эти условия попадают в RSS-запрос до загрузки
   карточек. Здесь же можно выбрать до пяти регионов и найти до пяти позиций
   ОКПД2 по коду или названию; поиск ОКПД2 начинается с трёх символов.
5. Выберите первую RSS-страницу, три, пять или до десяти страниц и нажмите
   «Найти в ЕИС».
6. Проверьте счётчики: число RSS-элементов, тематических карточек и новых
   записей. История не смешивается с текущей выдачей. Последний результат,
   история, причины совпадения и личные отметки сохраняются за текущим
   пользователем в PostgreSQL.
7. В блоке «Сохранённые поиски» задайте понятное название и сохраните текущую
   фразу со всеми условиями ЕИС. Кнопка «Запустить сейчас» повторяет запрос без
   ручного заполнения формы; рядом отображаются время, число совпадений и число
   новых записей последнего запуска. «Изменить условия» только возвращает
   сохранённые значения в форму. Раскройте «Историю», выберите запуск и
   переключите «Только новые»: для первого запуска это вся выдача, для
   следующих — карточки, которых не было непосредственно перед ним.
   В открытой истории проверьте сводные показатели и график совпадений/новых
   карточек. Нажмите «Создать копию», измените название или основные условия и
   убедитесь, что новая карточка сохранила расширенные фильтры исходного поиска.
8. Выберите от двух до пяти карточек текущей выдачи и нажмите «Сравнить»,
   чтобы открыть их поля в одной таблице. Значение «Не передано» означает,
   что его не было в разрешённом ответе источника.
9. Откройте detail карточки и нажмите «Дополнить из ЕИС». Проверьте срок
   подачи, место поставки, контакты, обеспечение и ссылки на документы.
   Повторная кнопка обновляет эти поля; фоновое обогащение не выполняется.
10. Сохраните личную заметку, теги и дату следующего действия. Вернитесь в
    выдачу и проверьте фильтр по тегу. На /dashboard проверьте счётчики
    просроченных и сегодняшних действий и переход к ближайшим карточкам. На
    /tenders проверьте поиск, личные статусы, тег, мониторинг, сортировку и
    переход между страницами; выбранные параметры должны оставаться в URL.
    Нажмите «Изменить отметку» на карточке и сохраните статус, теги и дату без
    перехода в detail. В ручной выдаче выберите несколько карточек, массово
    назначьте им теги/дату, затем статус; скрытие и архивирование должны
    запросить подтверждение. Данные другого пользователя не должны быть видны.
11. Выгрузите текущую видимую или выбранную выдачу кнопками CSV/XLSX. В
    истории запуска проверьте отдельные кнопки «Новые CSV/XLSX».
12. Если нужны условия, которых ещё нет во встроенной форме, вставьте в
   «Расширенных фильтрах ЕИС» RSS-ссылку, созданную самим порталом. Она
   полностью заменяет встроенные условия.

Новый и сохранённый поиск идут только после явного нажатия. Сохранение запроса
не создаёт расписание, ленту мониторинга или уведомление.
`RSS_LIVE_POLLING_ENABLED=false` остаётся
выключенным. Не используйте обход TLS, CAPTCHA, cookies или прокси.

Если Docker не доверяет сертификату ЕИС, используйте только официальные CA по
[`deploy/local-ca/README.md`](../deploy/local-ca/README.md), затем перезапустите
`web`, `queue` и `scheduler`.

Обычное обновление страницы, `docker compose restart` и пересоздание сервисов
не удаляют эти данные: PostgreSQL использует именованный Docker volume.
Команда с `down -v` или ручная очистка Docker volumes удаляет локальную базу
и должна применяться только когда это действительно нужно.

## Проверки

```powershell
make test
docker compose -f compose.local.yml -f compose.local.dev.yml exec -T web vendor/bin/pint --test
docker compose -f compose.local.yml -f compose.local.dev.yml exec -T web vendor/bin/phpstan analyse --memory-limit=1G
npm run build
```

`make test` запускает отдельный Compose-сервис с `APP_ENV=testing` и SQLite
`:memory:`. Не запускайте `php artisan test` внутри `web`: этот контейнер
подключён к постоянной локальной PostgreSQL. Дополнительная проверка в базовом
test case аварийно остановит тесты, если изоляция базы будет нарушена. В CI
дополнительно разрешена только выделенная PostgreSQL-база, имя которой
оканчивается на `_testing`.

`web`, `queue`, `scheduler`, PostgreSQL, Redis и Vite — части local runtime.
Их успешный запуск подтверждает только локальную среду. Он не включает
production, legal-документы, Telegram webhook, платежи или уведомления.
