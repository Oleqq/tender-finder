## Экран и доказательство выбора

На `/demo` отдельная галочка изначально снята. Текст показывает тариф,
сумму за период, период 1/3/12 месяцев, предварительное уведомление и отмену.
Изменение тарифа или периода сбрасывает флажок. Без флажка заказ остаётся
разовым. Запрос принимает boolean `auto_renew`, по умолчанию false;
цена/владелец/валюта/провайдер из клиента не принимаются.

Согласие фиксируется в snapshot `subscription_orders.terms`: флаг,
версия `auto-renew-2026-11-02-v1`, серверное время, провайдер согласия,
сумма/срок и версии юридических документов. Повтор с тем же ключом и другим
выбором отклоняется 409. Успешный заказ с флажком создаёт одну запись
`subscription_renewals`; ожидание, ошибка или отмена оплаты не создают её.
Старые заказы и подписки автоматически в автопродление не переводятся.

## Расписание и уведомления

`subscriptions:send-renewal-notices` вызывается каждую минуту в фоне с lock.
Обрабатываются до 100 due-записей; блокировки идут user → renewal → subscription.
Тариф/сумма/валюта/период берутся из подтверждённого серверного заказа.
Согласие demo не используется для настоящего провайдера.

Уведомление планируется за 24 часа с запасом 5 минут на запуск и транспорт.
Текст содержит сумму, период, дату по Москве и подписанную ссылку; кнопка
«Отменить автопродление» ведёт туда же. Telegram получает только реальные
провайдерские записи с подтверждённой привязкой Telegram ID. Обычные
настройки тендерных уведомлений не отключают сервисное сообщение подписки.

Demo записывает `demo_recorded` локально, без Telegram и платежных API.
Для будущего боевого пути точка `registerConfirmed` принимает только
succeeded-заказ, соответствующий подписке, с отдельным согласием. Вызывающий
provider webhook обязан сначала самостоятельно подтвердить платёж через API.
Сейчас единственный runtime-writer этой точки — успешная demo-оплата.
Тип `yookassa` зарезервирован и проверен изолированными fixtures.

При задержке отправки эффективная дата сдвигается минимум на 24 часа
после успешного уведомления. Ошибка доставки не создаёт `notice_sent_at`;
повтор — через 5 минут для временной ошибки или через час для отказа чата.
Повторный нормальный запуск не отправляет уже учтённое уведомление.
Как и у обычной доставки Bot API, нельзя гарантировать exactly-once при
потере подтверждения сети или сбое БД после успешной внешней отправки.
Статус sent означает подтверждение Bot API, не прочтение человеком.

## Отмена и окончательная проверка перед списанием

- `/cancel` в личном чате сразу отключает все собственные будущие продления.
  Actor должен совпадать с ID личного чата; группы, bots и несовпадающий actor
  не меняют подписки и не раскрывают ссылки. Неизвестная команда аккаунт не создаёт.
- Отмена фиксируется до отправки ответа бота. `telegram_updates.command_result`
  хранит минимальный результат. Если ответ потерялся, повтор этого update/job
  возвращает тот же результат и не отменяет новое согласие, данное позднее.
- Сервер закрывает свои активные расписания и `auto_renew` настоящих подписок,
  даже если запись расписания не успела создаться. `retry_at` и разрешённая дата
  списания очищаются; оплаченные end date, status и entitlement сохраняются.
  Журнал `subscription_renewal_events` сохраняет прежние события и отмену.
- `/subscriptions/renewals` и POST отмены доступны своему авторизованному
  пользователю также после истечения доступа. Чужие записи дают 404.
- Подписанная `/renewal/{uuid}/cancel` даёт ограниченное право отменить одну
  подписку. GET ничего не меняет; POST требует CSRF и явной кнопки. Подмена
  подписи даёт 403. Ссылка не публикуется в логах; страница no-store/no-referrer/noindex.
- Stars, trial и ручные grants не становятся новыми автопродлениями.
  Возврат уже совершённого платежа — отдельный процесс.

`readyForCharge` остаётся только диагностикой, а не разрешением отложенному
заданию использовать старый снимок. Для сохранённого способа оплаты применяется
`YooKassaClient::createRenewalPayment`: user → renewal → subscription блокируются
так же, как при отмене. Проверяются свежий флаг, источник/владелец, согласие,
уведомление и 24 часа после него, исходная и разрешённая даты. Только затем
внутри этой транзакции вызывается провайдер. Если отмена уже зафиксирована,
возвращается `null` без HTTP; повторные попытки также проходят этот путь.

Цена, RUB и metadata задаются серверным расписанием. Вызывающий будущий billing
код должен передать проверенный сохранённый способ оплаты, фискальные данные
и устойчивый ключ идемпотентности. Обычный `createPayment` с `payment_method_id`
теперь отклоняется: обойти отмену через низкоуровневый клиент нельзя.
Внешний запрос, уже начавшийся до получения отменой блокировки, не является
новым запросом после подтверждённой отмены; его сверка/возврат остаются отдельными.

У ЮKassa отключение автоплатежей означает прекращение использования сохранённого
способа на стороне магазина, а не вызов отдельного API удаления карты:
[официальный порядок](https://yookassa.ru/developers/payment-acceptance/scenario-extensions/recurring-payments/basics).
Тесты используют fixtures и HTTP fake; ни настоящий charge worker, ни новые
провайдерские продажи этим кодом не активируются.
