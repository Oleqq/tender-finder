# Демонстрация: триал → подписка

Реализация 28 октября 2026. Это изолированная заглушка внешнего веб-канала,
не тестовый магазин ЮKassa и не разрешение продавать доступ. Реальных списаний,
чеков, webhook, возвратов и запросов в ЮKassa нет. `YOOKASSA_ENABLED=false`.

## Как пройти

1. Локально включить `DEMO_CHECKOUT_ENABLED=true`, применить миграции и открыть
   `/demo` в отдельном профиле браузера. По умолчанию флаг выключен.
2. На VPS дополнительно нужна приватная подписанная ссылка, созданная в консоли:
   `php artisan demo:reviewer-link --hours=24` (допустимо 1–168 часов).
   Открыть её во внешнем браузере. Ссылка даёт право создать **нового** гостя,
   не входит в существующий аккаунт. Не публиковать её в Mini App, логах или Git.
3. «Начать демонстрацию» → два согласия → однократные 72 часа Basic.
   Браузер хранит собственный аккаунт в cookie. Потеря cookie не восстанавливает
   прежние данные и не открывает чужой аккаунт.
4. Вверху рабочих экранов демо-гостя есть «Демонстрация · Мой доступ».
   На `/demo` можно завершить период **только этого гостя**, сохранив факт
   использованного триала. Эта QA-кнопка не меняет обычные аккаунты/выдачи.
5. Выбрать Basic / Pro / Ultra, 1 / 3 / 12 месяцев. Показаны полная сумма,
   лимит, дата окончания и отсутствие автопродления. Создать заказ, затем
   выбрать тестовый исход: подтверждение, ожидание, ошибка или отмена.
6. После подтверждения перейти к мониторингам и явно возобновить нужные.
   Ранее поставленные на паузу не включаются сами. Уведомления за прошлое
   время не отправляются. После окончания подписки можно купить новый период.

Повтор после ошибки/отмены создаёт новый заказ с новым ключом; выбранные
тариф и период сохранены. Пока заказ ожидает оплаты, другой тариф требует
отмены текущего заказа. Обновление, статус запроса и `?success=true` не выдают
доступ. Кнопка подтверждения работает только у авторизованного демо-гостя;
обычный пользователь и владелец не могут её вызвать для своего аккаунта.

На production право checkout истекает вместе с reviewer-сессией; для новой
проверки нужна новая ссылка. Cookie аккаунта сохраняется отдельно. Флаг
`DEMO_CHECKOUT_ENABLED=false` закрывает все demo-маршруты и платные действия
демо-гостей. Старый `TEMP_FULL_ACCESS_UNTIL` не продлевается и не влияет на demo.
Demo-аккаунты не связываются с Telegram и не принимают/выдают командные приглашения.

## Матрица доступа

| Состояние | Рабочие изменения, проверки, экспорт | Аналитика | Мониторинги |
|---|---|---|---|
| preview | Закрыты; доступны согласия, документы, поддержка, статус | Краткая для уже доступных материалов | Создание закрыто |
| trialing | Доступны строго до `ends_at`, 72 часа | Basic | 3 |
| expired | Только чтение материалов; закрыты изменения, новые запуски, CSV/XLSX/ICS | Краткая | Активные замораживаются; паузы сохраняются |
| Basic | Доступны до срока | Краткая | 3 |
| Pro | Доступны до срока | Окно подачи, полнота, сигналы, план | 10 |
| Ultra | Доступны до срока | Pro + бюджеты, сценарии, история, чек-лист | 30 |
| owner | Прежний владельческий доступ | Ultra без override | Прежний безлимит |
| Developer | Прежнее право override, срок выдачи не продлевается | Выбранный тариф | Выбранный лимит |
| demo guest | Та же последовательность preview/trial/expired/active; явно помечена | По фактическому тарифу | По триалу/заказу |

Действующие admin grants и прежний переход в preview после гранта без
использованного триала сохранены. Административный сброс trial работает как ранее.
Покупка при действующем доступе (включая грант) не предлагается и отклоняется.
Настройки аккаунта, отключение календарной ссылки, пауза/удаление мониторинга,
документы и поддержка остаются доступны без подписки. Рабочие изменения после
окончания срока дают JSON 403 `access_required` либо переход на `/plans`.

## Серверный контракт

- `SubscriptionCatalog` — единый каталог девяти сумм в копейках, лимитов,
  периодов и описаний. `/pricing` и `/pricing/dark` остаются информационными:
  `PricingPageRenderer` подставляет каталог в шаблоны `resources/pricing`.
  `php artisan pricing:render` обновляет автономные HTML в `docs/`;
  тест требует их полного совпадения с серверным выводом.
- `subscription_orders`: UUID, владелец, тариф, календарные месяцы, сумма,
  RUB, snapshot условий/версий документов, provider `demo`, `is_demo`, состояние,
  ключ идемпотентности, фиксированные даты, срок подтверждения, уникальная
  связь с подпиской. `subscription_order_events` хранит переходы.
  Историческая таблица Stars `payments` не используется.
- `POST /demo/orders`: только `plan_code`, `duration_months`, `idempotency_key`.
  Сумма, владелец, лимит, валюта, состояние и ID из запроса отклоняются.
  Один незавершённый заказ на пользователя, даже при разных ключах двух вкладок.
- `POST /demo/orders/{id}/confirm`: только `outcome`, после проверки feature
  flag, reviewer-сессии, гостевой личности и владельца заказа. Серверный
  `CheckoutProvider` изолирует подтверждение; единственная реализация —
  `DemoPaymentProvider`. Будущий реальный провайдер обязан независимо проверять
  платёж; передаваемый демо-исход нельзя использовать как доказательство оплаты.
- `GET /demo/orders/{id}` только читает состояние. Никакие return URL/callback
  не подтверждают оплату. Все изменяющие запросы защищены CSRF и throttling.
- Создание и подтверждение блокируют строку пользователя; затем заказ.
  Транзакция включает subscription, entitlement, связь заказа и аудит успеха.
  Терминальный заказ не меняется повторным подтверждением/отменой.
- Заказ действует 30 минут. Начало фиксируется при создании заказа, календарный
  конец показывается перед подтверждением и затем не сдвигается. Если нет
  исходного числа в целевом месяце, берётся последний доступный день, время МСК
  сохраняется: 31 января → 28/29 февраля; 29 февраля +12 → 28 февраля.
  Последний день не «прилипает»: 30 апреля +1 → 30 мая. Это не 30/90/360 дней.
- `source=demo`, entitlement `metadata.is_demo=true`, access `mode=demo`.
  Lifecycle завершает этот источник. При отсутствии scheduler сроки всё равно
  проверяют AccessService, HTTP middleware, matching, выдача уведомлений и ICS.
  Фоновые RosTender/B2B запросы привязанных фидов проверяют действующий доступ;
  общие публичные каталоги могут продолжать наполнять общий кеш без новых
  персональных совпадений истёкшим пользователям.
- Покупка замораживает оставшиеся активные мониторинги и прекращает старые
  queued/failed доставки до выдачи нового доступа. Resume задаёт новое
  `monitoring_started_at`, соблюдает лимит и не рассылает старые карточки.

Публичные тарифы и `/plans` не получают checkout-кнопку. В Mini App продажа
цифровой услуги через стороннюю кассу не подключена; граница проверена по
[официальным правилам Telegram](https://core.telegram.org/bots/payments-stars).

## Проверка и выпуск

`DemoCheckoutTest` проверяет 72 часа без scheduler, все девять комбинаций,
конец месяца/високосный год, four outcomes, повторы и две логические вкладки,
подмену полей/владельца/заказа, истёкший quote, закрытый production без signed
сессии, отключение флага, admin grant во время заказа, повторную покупку,
фоновые совпадения и старые failed-уведомления. Существующие workspace-тесты
теперь явно выдают Basic фикстурам через `UserFactory::withAccess()`;
обычный factory по-прежнему создаёт preview.

Полный PostgreSQL CI обязателен для выпуска; локальный переносимый PHP
не содержит XMLWriter, SQLite не поддерживает один существующий фильтр ленты.
Эти ограничения локального runtime не являются пропуском production-проверок.
Ручной протокол и скриншоты этого этапа сохраняются вне Git в
`/tmp/tf-demo-qa`: новый гость/согласия, ошибка/отмена/ожидание/успех,
клавиатура, сеть, загрузка, две вкладки, reload/back, обе темы и
320/390/480/1280 px. Физический Telegram-клиент не проверяет внешний checkout.

Порядок: миграция `2026_10_28_120000_create_subscription_orders`, оба remote main,
зелёный CI точного commit, проверенная backup PostgreSQL, штатный deploy,
health/queue/scheduler/migrations/assets, затем `.release-commit`. Флаг demo
включать на VPS только для защищённой reviewer-проверки. Реальные триалы
и данные не сбрасывать. Без проверенной backup деплой не проводить.

## Перед настоящими платежами

Нужны: восстанавливаемый аккаунт и подтверждённая связь с Telegram; утверждённые
продавец/оферта/политика, тип покупателя и командные лицензии; фискализация,
реквизиты чека, возвраты и поддержка; настоящий адаптер ЮKassa с проверкой
статуса/суммы/валюты/заказа, защищённым webhook и сверкой; тестовый магазин
и отдельное согласование запуска внешних продаж. Cookie-гость и эта заглушка
не заменяют эти решения. Автосписания, prorating и смена активного тарифа
в данный этап не входят.
